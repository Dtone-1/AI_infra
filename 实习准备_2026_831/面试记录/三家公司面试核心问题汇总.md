# 三家公司面试核心问题汇总

> 来源：通智科技、万象智维、智象未来三次面试记录。  
> 整理原则：只保留具有代表性、需要重点复习的问题；同一知识点下的连续追问进行了合并，不再逐条罗列细碎追问。

---

# 一、通智科技

## 1. Qwen3.5 与 Qwen3 的模型结构有什么区别？
重点包括：Qwen3.5 的 Hybrid 架构、GDN 与 Full Attention 的区别，以及引入 GDN 后 KV Cache 和状态管理发生了什么变化。

## 2. 为了适配 Qwen3.5，你对抢占重算和 CUDA Graph 做了哪些修改？
需要说明 Hybrid 模型下 KV Cache 与 GDN state 的资源检查、状态管理，以及 CUDA Graph 为什么使用、解决了什么开销。

## 3. Qwen3.5 的多模态输入是怎么接入 nano-vLLM 的？
需要能够讲清楚文本与图片两条预处理链路、视觉编码、图片特征如何与文本隐藏状态融合。

## 4. 你的 MTP 是怎么实现的？
重点包括 Draft Model 从哪里来、一次预测多少 token、主模型如何验证、接受长度和接受率怎么设置与统计。

## 5. 你的 KV Cache 压缩具体是怎么做的？
需要说明周期压缩、SnapKV 的重要性打分、保留哪些 token、如何重新整理 KV Block，以及压缩后逻辑长度和物理长度如何维护。

## 6. KV Cache 压缩后位置不再连续，位置编码和 Sequence 长度怎么处理？
这是压缩机制中的工程一致性问题，需要解释逻辑 token 位置不能简单跟随压缩后的物理存储位置。

## 7. TP=4 时 Attention 和 FFN 的权重是怎么切分的？卡之间在哪里通信？
重点包括 Q/K/V/O、Up/Gate/Down Projection 的切分方式，以及 All-Reduce、Gather 等通信发生的位置。

## 8. KV Cache 压缩对精度、并发能力和 Decode 吞吐有什么影响？
不仅要会报实验结果，还要解释为什么显存下降后零抢占并发和 Decode 吞吐会发生变化。

## 9. 你的 GEMM Kernel 做了哪些优化？
需要从朴素 GEMM 开始，讲线程块/Warp/线程分工、Shared Memory、异步搬运、双缓冲等优化过程。

## 10. FlashAttention 解决的核心问题是什么？具体是怎么优化 Attention 的？
不能只停留在“让 Attention 更快”，需要能解释减少 HBM 读写、中间矩阵物化和分块计算的思想。

## 11. Continuous Batching 是什么？为什么请求结束后可以立即插入新请求？
需要解释静态 Batch 的问题，以及推理框架如何依靠请求级状态、调度器和 KV Cache 管理实现动态组 Batch。

## 12. 常见投机解码方法你了解哪些？EAGLE 系列有什么演进？
面试官重点追问了 EAGLE 1/2/3 以及 Draft/Verify 类投机解码方案。

## 13. Chunked Prefill 是什么？为什么要做？
重点解释长 Prefill 为什么会阻塞 Decode，以及切分长 Prompt 后如何改善调度公平性和延迟。

## 14. 你的 C++ / CUDA 基础怎么样？CUDA Kernel 如何被 Python 调用？
包括 C++ 继承/虚继承、CUDA 扩展的 Python 调用方式，以及能否现场写最基础的 GEMM Kernel。

## 15. DeepSeek 等主流模型架构你是否真正了解？
面试官根据简历中“熟悉 Qwen、DeepSeek 等主流架构”进行了反向核验。

# 二、万象智维

## 1. 你做 Qwen3.5 推理与动态 KV Cache 压缩项目的核心优化目标是什么？
需要明确区分：模型适配解决的是“能不能跑”，KV Cache 压缩主要解决长上下文下的显存压力和并发问题。

## 2. 大模型推理时显存主要消耗在哪些部分？
需要能够说明模型权重、KV Cache、激活/临时工作区和框架预留等显存组成。

## 3. 单请求的 KV Cache 显存应该怎么计算？
面试官进一步给出了 Qwen3.5 35B、Q4、4K 上下文场景，要求能够根据层数、KV Head、Head Dim、数据类型和上下文长度估算显存。

## 4. 如果单卡显存放不下模型，有哪些办法让模型跑起来？
需要系统回答 Tensor Parallel、量化、CPU/NVMe Offload 等方案，而不仅仅想到多卡。

## 5. Offload 是什么？实际工程中怎么做？
需要了解模型权重或 KV Cache 在 GPU、CPU、甚至更低层存储之间搬运时的基本工作方式和性能代价。

## 6. Prefill 和 Decode 分别受什么性能瓶颈限制？
核心是 Prefill 更偏计算受限，Decode 更偏显存带宽/访存受限，并能进一步解释原因。

## 7. 大模型推理加速有哪些常见手段？
除了 FlashAttention，还需要能够从算子、批处理/调度、量化、并行、KV Cache、投机解码等维度完整回答。

## 8. 算子优化一般是怎么做的？
需要能够从瓶颈分析出发，说明访存、计算、线程组织、Shared Memory、寄存器、异步搬运和双缓冲等常见优化方法。

## 9. Qwen3.5 Hybrid 中 Full Attention 和 GDN 分别保存什么状态？
重点区分不断增长的 KV Cache 与固定大小的 recurrent state / convolution state。

## 10. Hybrid 模型发生抢占后，GDN 的 recurrent state 怎么恢复？
这是面试官重点追问的工程问题，需要解释状态快照、重算或者重新构建状态的机制。

## 11. MTP 只有 Draft Token 接受率还够不够？它最终让 TPOT 提升了多少？
面试官强调：投机解码最终应该看端到端收益，而不能只报一个接受率指标。

## 12. SnapKV 为什么可以判断哪些历史 KV 可以删除？
需要解释 Query 对历史 Key 的注意力分数如何作为重要性依据，以及这种策略为什么可能造成精度损失。

## 13. 已经删掉的历史 KV，如果未来突然变重要怎么办？
这是 KV Cache 压缩的核心局限，需要认识到基于历史注意力的重要性预测并不能保证未来仍然准确。

## 14. 为什么使用 4×RTX 3090？TP=4 下每层有哪些通信？
需要完整说明 Embedding、Attention、MLP、LM Head 等位置的张量切分和跨卡通信。

## 15. 四张 GPU 在物理上通过什么连接和通信？
不仅要知道 NCCL，还要区分 PCIe、NVLink 等底层互联及其对通信带宽的影响。

## 16. 你了解量化、模型后训练、稀疏优化或 MoE 吗？
这些都是面试官用于判断知识边界和是否适合端侧推理优化岗位的问题。

## 17. 如果换成 RK3588、AMD、昇腾等非 NVIDIA 硬件，你能不能做模型部署和推理优化？
该岗位明显重视跨硬件适配能力、算子优化能力和端侧部署能力。

# 三、智象未来

## 1. 为什么选择 nano-vLLM，而不是直接学习正式版 vLLM？
需要说明 nano-vLLM 代码规模更小、适合理解核心机制，以及后续如何从学习框架迁移到真实 vLLM。

## 2. 为什么选择适配 Qwen3.5？Qwen3.5 相比 Qwen3 最大的结构变化是什么？
核心是 Hybrid 架构以及 GDN + Full Attention 对推理框架状态管理提出的新要求。

## 3. 一个请求从进入 nano-vLLM 到最终生成 token，完整生命周期是什么？
面试官明确要求从“框架工程角度”而不是只从 Transformer 数学计算角度讲，请求涉及 Sequence、Scheduler、ModelRunner、BlockManager、Prefill、Decode 和采样等模块。

## 4. ModelRunner 和 BlockManager 之间到底如何传递信息？
需要能回答具体参数和职责，而不是只说“BlockManager 管 KV Cache”。

## 5. BlockManager 的完整工作流程是什么？
重点包括初始化、Block 分配、BlockTable、Prefix Cache / 哈希匹配、引用计数、释放与回收等具体流程。

## 6. Qwen3.5 Hybrid 适配过程中，你具体改了哪些模块？最困难的地方是什么？
需要区分模型结构层修改与推理框架工程修改，并明确 GDN state 的新增管理逻辑。

## 7. GDN 的状态放在哪里管理？为什么不能继续只用 BlockManager？
面试官进一步追问了新增 StateManager 的文件、类和状态生命周期。

## 8. Qwen3.5 多模态输入的完整链路是什么？
从图片预处理、Pixel Values / THW，到 Vision Encoder、Image Embedding，再到文本 Placeholder 替换，都要能顺下来。

## 9. Image Placeholder 的数量到底是怎么计算出来的？
这是多模态适配中的一个具体工程细节，要求能从图片尺寸、Patch/Merge 后的视觉 Token 数量解释。

## 10. Pixel Values、THW 分别给谁使用？Vision Encoder 的输入输出是什么？
面试官连续追问了视觉编码器前后的张量和信息流。

## 11. RoPE / MRoPE 到底做什么？输入和输出是什么？
不能只会说“增加位置信息”，还需要知道它作用在 Q/K 上，以及位置 ID、旋转后的 Q/K 等输入输出关系。

## 12. AI 帮你完成项目的比例有多大？你自己真正学到了什么？
这是对项目真实性和个人掌握程度的核验，需要能说明如何拆任务、审代码、验证结果，而不是简单说“AI 帮我写的”。

## 13. 你的性能测试是怎么设计和压测的？
需要解释实验设置、吞吐、并发、KV Cache Block 等指标，以及测试脚本具体做了什么。

## 14. KV Cache 压缩为什么要做？SnapKV 的思路来自哪里？
不仅要讲实现，还要说明参考论文、原始方法和自己项目中的改动。

## 15. Prefix KV Cache / Block Hash 是怎么计算和匹配的？
面试官深入追问了 Prefix Cache 的哈希目的、Block 粒度匹配和哈希生命周期。

## 16. FlashAttention 是什么？Softmax 的作用是什么？
这是最基础的模型与推理优化知识，面试官用它来检查基础是否扎实。

## 17. 你为什么认为自己适合做 AI Infra？你的优势是什么？
面试官明确指出基础偏弱后，重点考察学习能力、执行力、成长性和是否真正愿意长期投入这个方向。

## 18. 你的 C/C++ 能力怎么样？除了 Python 还能做哪些工程开发？
该岗位不仅看 Python，还会关注 C/C++、CUDA 和底层工程能力。

## 19. 为什么同时学习推理框架和 CUDA/GEMM 算子？
需要能说明 Framework-level 和 Kernel-level 两个层次在 AI Infra 中的关系。

## 20. 你手写 GEMM 后是怎么和 cuBLAS 做性能对比的？
需要知道 CUDA Event 等 GPU 计时方法、Warmup、重复测试以及吞吐计算方法。

# 三场面试共同高频主题

从三家公司来看，最值得优先复习的内容集中在以下几个方向：

1. **Qwen3.5 Hybrid 架构**：GDN、Full Attention、KV Cache、recurrent/conv state。
2. **nano-vLLM / vLLM 请求完整生命周期**：Sequence、Scheduler、ModelRunner、BlockManager。
3. **KV Cache 管理**：PagedAttention、BlockTable、Prefix Cache、哈希、分配与释放。
4. **KV Cache 压缩**：SnapKV、重要性评分、物理压紧、逻辑/物理长度、精度损失。
5. **多卡 TP=4**：Attention/MLP 权重切分、All-Reduce/Gather、GPU 互联。
6. **Prefill / Decode 性能瓶颈**：计算受限 vs 访存受限。
7. **FlashAttention、Continuous Batching、Chunked Prefill** 等推理框架核心优化。
8. **MTP / 投机解码**：Draft、Verify、Accept、端到端 TPOT 收益。
9. **CUDA / GEMM**：线程组织、Shared Memory、异步搬运、双缓冲、性能测试。
10. **量化、Offload、端侧部署**：单卡显存不足时的系统解决方案。
