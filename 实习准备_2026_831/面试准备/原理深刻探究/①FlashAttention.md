# ① FlashAttention

## FlashAttention 算子入口

### 1. flash\_attn\_varlen\_func\(\)和flash\_attn\_with\_kvcache\(\)是什么，是做注意力计算的两个算子吗，介绍一下

对，可以把 `flash_attn_varlen_func()` 和 `flash_attn_with_kvcache()` 理解成 **FlashAttention 提供的两类高性能注意力计算接口，底层最终都会调用优化后的 GPU 算子，但是它们主要针对的推理阶段不一样**。在我的 nano\-vLLM 项目里，`flash_attn_varlen_func()` 主要用于 **Prefill**：因为这一轮可能同时有多个长度不同的 Prompt，比如 A 有 1000 个 Token、B 有 500 个 Token，ModelRunner 会把它们展平成一条 `[1500, num_heads, head_dim]` 的 Q/K/V 数据，再通过 `cu_seqlens=[0,1000,1500]` 告诉 FlashAttention 每条请求的边界，这样就不需要为了凑成矩形 batch 去做大量 padding；**算子内部仍然完成正常的 \(QK^T\)、softmax、再乘 V，只是使用 FlashAttention 的分块方式减少中间矩阵的显存读写。**官方接口中 `flash_attn_varlen_func` 的 Q/K/V 第一维就是整个 batch 的总 Token 数，并通过 `cu_seqlens_q`、`cu_seqlens_k` 描述不同请求的长度。 

而 `flash_attn_with_kvcache()` 更偏向 **Decode 推理**，因为 Decode 时每条请求通常只有 1 个新的 Query，但它需要读取很长的历史 K/V。这个接口专门针对这种“小 Query、长 KV Cache”的情况做了优化，可以直接接收已经存在的 KV Cache 和当前缓存长度，让当前 Q 与历史 K/V 做 Attention；官方实现还支持把本轮新产生的 K/V原地追加到 KV Cache，并支持 `block_table` 这种分页 KV Cache 的地址映射。FlashAttention 官方也明确把这个接口定位为 iterative decoding 的推理优化，重点就是尽可能高效地读取 KV Cache。

所以我会简单记成：**`flash_attn_varlen_func()`**** 主要解决 Prefill 阶段“多条不同长度序列一起算 Attention”的问题；****`flash_attn_with_kvcache()`**** 主要解决 Decode 阶段“当前少量 Query 高效读取大量历史 KV”的问题。它们没有改变 Attention 的数学原理，主要区别是输入数据组织形式和针对的 GPU 执行场景不同。**

## 核心原理与计算基础

### 2. flashattention的原理是什么

FlashAttention 的核心原理是：**不改变 Attention 的数学公式，而是改变它在 GPU 上的计算和访存方式，尽量避免把巨大的中间注意力矩阵写回显存。**普通 Attention 会先算 $(QK^T)$，得到一个 `[seq_len, seq_len]` 的注意力分数矩阵，再做 softmax，最后乘 V；当序列很长时，这个中间矩阵非常大，比如 16K 长度时就是一个 $(16384\times16384)$的矩阵，频繁从显存读写会非常慢，而且占显存。

**FlashAttention 的做法是把 Q、K、V 按小块切分，每次只把一小块搬到 GPU 片上更快的 SRAM，比如 shared memory 和寄存器里，然后在片上直接完成这部分**$(QK^T)$**、softmax 和乘 V，算完以后只把最终输出写回显存，中间那张完整的 Attention 矩阵根本不落显存。**

**难点在于 softmax 原本需要看到整行数据才能归一化，所以 FlashAttention 使用一种在线 softmax 的方法，在分块计算过程中维护当前最大值和归一化系数，后面读到新的 K/V 块时再更新，因此即使分块算，最后结果仍然和标准 Attention 一致。**它最大的收益就是**大幅减少 HBM 显存和 GPU 片上存储之间的数据搬运**，所以 FlashAttention 本质上是一种 IO\-aware 的 Attention 优化；它不是把 $(O(n^2))$ 的 Attention 数学计算复杂度变没了，而是**减少了中间结果的显存占用和读写次数**，因此在长序列场景下会明显更快、也更省显存。

### 3. 举个具体的例子详细的说明flashattention的整个过程

可以用一个很小的例子把 FlashAttention 整个过程走一遍。假设现在只看 **1 个 Attention Head**，序列长度是 8，每个 Q、K、V 都是 4 维，所以原始的 `Q、K、V` 形状都是 `[8,4]`。普通 Attention 会直接计算 `Q @ K^T`，一次生成完整的 `[8,8]` 注意力分数矩阵，把它写到显存里，再从显存读出来做 softmax，最后再乘 V；真实模型如果是 16K Token，这个中间矩阵就会非常大。

FlashAttention 不这么做，它假设一次只处理 4 个 Token，把 Q、K、V 分块。比如现在计算第 4～7 个 Token 的 Query，就**先把 ****`Q[4:8]`**** 这个 ****`[4,4]`**** 小块从显存搬到 GPU 片上更快的 shared memory 或寄存器里，**然后先读取第一块 `K[0:4]、V[0:4]`，分别也是 `[4,4]`，直接在片上算出一个 `[4,4]` 的局部注意力分数。假设我们只看其中第 6 个 Token，它和前四个 K 算出来的分数是 `[1,2,0,-1]`，普通 softmax 本来需要等它和所有历史 K 都算完以后才能归一化，但 FlashAttention 会**先记录这一块的最大值 ****`m=2`****，然后算指数和**，也就是 `l=e^(1-2)+e^(2-2)+e^(0-2)+e^(-1-2)`，大约等于 `1.553`，**同时立刻用这些指数权重去乘对应的 V，得到一个“暂时还没有最终归一化”的局部输出**；这个 `[4,4]` 的分数矩阵算完就可以丢掉，不需要写回显存。接下来再把第二块 `K[4:8]、V[4:8]` 搬进片上，对于第 6 个 Token，因为是因果注意力，它只能看到位置 4、5、6，位置 7 会被 mask 掉，假设新的有效分数是 `[3,1,2]`。这时发现新的最大值变成了 3，FlashAttention 就利用在线 softmax 更新前面的结果：**旧块原来的最大值是 2，所以旧的指数和需要乘 ****`e^(2-3)`**** 重新缩放，然后再加上新块的 ****`e^(3-3)+e^(1-3)+e^(2-3)`****，于是新的归一化和大约变成 ****`2.07`****；**前面已经算好的 V 加权结果也按照同样比例缩放，再加上这一块新的 V 加权结果。**等所有 K/V Block 都扫描完以后，最后再除以累计的归一化系数**，就得到第 6 个 Token 最终的 Attention 输出。其他 Query Token 也是完全相同的过程。这样原本需要生成完整 `[8,8]` 分数矩阵，现在每次只产生一个 `[4,4]` 的临时小块，而且这个小块一直在 GPU 片上完成 **`QK^T → softmax 更新 → 乘 V`**，算完马上丢弃，最终只把 `[8,4]` 的 Attention 输出写回显存。所以 FlashAttention 的核心过程就是：\*\*Q 分块 → K/V 分块 → 小块搬进片上存储 → 计算局部 `QK^T` → 用在线 softmax 维护最大值和归一化系数 → 立刻乘 V 累加输出 → 换下一块 K/V → 最后得到和普通 Attention 数学上等价的结果。\*\*它真正省下来的不是 Attention 的计算量，而是避免了完整注意力矩阵反复写入和读取显存，因此长序列下速度和显存效率都会明显更好。

### 4. 说一下softmax的原理和过程，举一个例子说明

Softmax 可以理解成：**把一组任意大小的分数，转换成一组 0 到 1 之间、并且加起来等于 1 的权重**。在 Attention 里，Q 和 K 做点积以后得到的只是相关性分数，比如某个 Query 对 3 个历史 Token 的分数是 `[1, 2, 3]`，这个数字本身还不能直接当成权重，所以 **Softmax 会先对每个分数做指数运算，再除以所有指数结果的总和**，也就是 $(p_i=\frac{e^{x_i}}{\sum_j e^{x_j}})$。为了数值稳定，工程上通常不会直接算 `exp(1)、exp(2)、exp(3)`，而是**先减去最大值 3，变成 ****`[-2,-1,0]`****，这样最终结果完全一样，但能避免指数太大导致溢出**。然后算指数，大约得到 `[0.135,0.368,1]`，总和大约是 `1.503`，再分别除以总和，最后得到大约 `[0.09,0.24,0.67]`。这意味着模型认为第三个位置最重要，占 67% 的注意力，第一个位置只占 9%。最后 Attention 就拿这几个权重去对对应的 V 做加权求和。所以 Softmax 的作用就是**把原始相关性分数变成可解释的概率式权重，而且会通过指数放大分数之间的差异，让分数高的位置获得更大的关注度**。在因果 Attention 里，还会先把未来 Token 的分数设成负无穷，经过 Softmax 后它们的权重就会变成 0，这样当前 Token 就不会看到未来信息。

## 面试总结与版本演进

### 5. 讲一下flashattention（面试版）

FlashAttention 的核心思想是不改变 Attention 的数学公式，而是**通过分块计算，减少 GPU 显存和片上存储之间的数据搬运**。正常 Attention 是先计算完整的 QKT，得到一个很大的注意力分数矩阵，再做 Softmax、再乘 V，**这个中间矩阵如果序列很长会非常大，而且要反复写入和读取 GPU 显存**。

FlashAttention 则不会生成完整的注意力矩阵。实际执行时 Q、K、V 本身已经在 GPU 显存中，它**先取一小块 Q 放到 GPU 片上更快的 Shared Memory 或寄存器中**，然后再依次读取一块一块的 K 和 V。对于当前 Q 块和第一个 K 块，先计算局部的 QKT，但是**因为后面还有其他 K 块没有读取，所以现在不能直接做最终 Softmax**。它会对每一行维护当前的**最大值、指数和，也就是归一化系数**，**同时把这一块 Softmax 对应的 V 加权结果先累加起来**。接着读取下一块 K、V，再得到新的注意力分数，**如果发现新的最大值比之前大，就利用在线 Softmax 的公式重新缩放之前保存的归一化系数和输出累加结果**，**然后把当前这一块的结果继续累加进去。**这样一直遍历完所有 K/V 块之后，就得到了和完整 Softmax 数学上等价的最终 Attention 输出，然后只把最终结果写回 GPU 显存。当前 Q 块完成以后，再处理下一块 Q，直到整个 Attention 计算结束。所以 FlashAttention 真正优化的不是 QKT、Softmax、乘 V 这些数学计算本身，而是避免把完整的 N×N 注意力矩阵写回显存，尽量让中间结果留在 GPU 片上完成计算，从而减少 HBM 读写，提高长序列 Attention 的速度，同时降低中间显存占用。

### 6. **flash attention有几个版本，各版本之间有什么区别**

FlashAttention 现在可以简单分成 **4 代**。**FlashAttention\-1** 是最早的版本，核心贡献就是我们前面讲的那套思想：把 Q、K、V 分块搬到 GPU 片上存储，在片上完成局部 \(QK^T\)、在线 Softmax 和乘 V，避免把完整的 \(N\\times N\) Attention 矩阵写回 HBM，所以它主要解决的是**显存读写太多和中间矩阵太大**的问题。

**FlashAttention\-2** 没有改变这个基本原理，主要继续优化 GPU 并行方式：减少一些非矩阵乘计算，并重新设计 thread block 和 warp 之间怎么分工，让更多 GPU 计算单元同时工作，所以相比 FA1 大约又能提升接近 2 倍的效率；目前像 A100、RTX 3090、RTX 4090、H100 这些卡都属于 FA2 的主要支持范围，所以**我的 3090 项目最相关的其实就是 FlashAttention\-2**。 

**FlashAttention\-3** 则主要是针对 H100/H800 这一代 Hopper GPU 做硬件级优化，它进一步利用** Tensor Core、TMA 和异步流水，把“数据搬运、矩阵乘法、Softmax”尽可能重叠执行**，同时**加入 FP8 支持**，所以重点已经从单纯分块变成了**怎么把 Hopper 的新硬件能力吃满**；论文里 H100 上 FP16 相比 FA2 可以达到大约 1\.5～2 倍加速。

到现在还有 **FlashAttention\-4**，官方实现已经采用 CuTeDSL，并面向 Hopper 和 Blackwell，比如 H100、B200 做进一步优化，可以理解成**继续针对更新一代 GPU 的执行模型重写底层 kernel**。 

所以面试里我会把四代的区别概括成一句话：**FA1 提出了“分块 \+ 在线 Softmax，减少 HBM 读写”的核心算法；FA2 主要优化并行划分，让 GPU 跑得更满；FA3 面向 Hopper，通过异步流水和 FP8进一步利用新硬件；FA4 再面向 Hopper/Blackwell，用新的 CuTeDSL 实现继续榨取新架构性能。它们的 Attention 数学公式基本没有变，主要变化都是“同样的 Attention 怎么在不同 GPU 上执行得更高效”。**
