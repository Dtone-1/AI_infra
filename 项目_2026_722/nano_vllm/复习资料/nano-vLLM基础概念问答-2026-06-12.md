# 基础概念问答复习笔记

## 整理范围说明

本文件整理的是本聊天窗口中从第一次概念提问“为什么大模型推理不能只靠 PyTorch 或 Hugging Face Transformers 的 `generate()` 循环完成，而需要 vLLM / nano-vLLM 这样的推理引擎？”开始，到当前已回答的“logits 是什么”为止的问答内容。整理方式为：保留原始问题表达，压缩回答为适合快速复习的高密度版本。

## 问答复习整理

## 1. 问题：为什么大模型推理不能只靠 PyTorch 或 Hugging Face Transformers 的 `generate()` 循环完成，而需要 vLLM / nano-vLLM 这样的推理引擎？这里的 Hugging Face Transformers 是什么？

### 复习版答案

**Hugging Face Transformers** 是一个常用的开源模型库，基于 PyTorch 等框架封装了模型结构、Tokenizer、权重加载和 `generate()` 文本生成接口。它解决的是“模型怎么加载、怎么跑起来、怎么生成文本”。

但 `generate()` 更适合单请求、小规模实验，不适合高并发服务化推理。大模型推理真正困难的是系统问题：

- 多个请求输入/输出长度不同；
- KV Cache 显存占用巨大且动态变化；
- Prefill 和 Decode 阶段计算特征不同；
- 需要动态 batch 调度，提高 GPU 利用率；
- 需要精细管理显存，避免碎片和浪费。

所以可以记成：

> **Transformers 的 `generate()` 是模型推理接口；vLLM / nano-vLLM 是推理系统/推理引擎。**

vLLM / nano-vLLM 多做的是：请求调度、Continuous Batching、KV Cache 管理、PagedAttention / block 管理、显存优化、吞吐和延迟优化。

---

## 2. 问题：预分配浪费，提高显存利用率，按 block 动态分配，这里的 block 是存储的单位吗？

### 复习版答案

是的，**block 可以理解成 KV Cache 的显存分配单位**。但它不是硬盘 block，也不是 CUDA 里的 thread block，而是推理引擎自己定义的 KV Cache 管理单位。

一个 block 通常存一段连续 token 对应的 K/V Cache。例如 `block_size = 256`，表示一个 block 可以存 256 个 token 的 KV Cache。

关系可以记成：

```text
Sequence：一个用户请求
Token：模型处理的基本单位
KV Cache：每个历史 token 在每层 Attention 中保存的 K/V 中间结果
Block：KV Cache 显存管理的基本单位
Block Table：记录某个 Sequence 使用了哪些物理 block
```

为什么省显存：  
传统方式可能按最大上下文长度预分配，例如每个请求都按 4096 token 预留；block 动态分配则是当前用了多少 token，就分配多少 block，生成变长时再追加，请求结束后回收。

一句话：

> **token 是模型处理的基本单位，block 是 KV Cache 显存管理的基本单位。**

---

## 3. 问题：大模型推理中，KV Cache 是显存大户。每一层、每个 attention head、每个历史 token 都会保存 K/V。这里的 attention head 什么意思？

### 复习版答案

**attention head** 是 Transformer 里一组独立的注意力计算通道，也可以理解成“一个看上下文关系的视角”。

Self-Attention 中每个 token 会生成：

```text
Q：Query，当前 token 想找什么信息
K：Key，历史 token 提供的匹配索引
V：Value，历史 token 携带的具体信息
```

Attention 的过程是：用当前 token 的 Q 去匹配历史 token 的 K，再按匹配程度加权汇总 V。

多个 attention head 就是多套 Q/K/V 投影并行工作，让模型从多个角度理解上下文关系。比如一个模型每层有 32 个 attention heads，就是每层并行做 32 组注意力计算。

KV Cache 为什么和 head 有关：  
每一层、每个 head、每个历史 token 都需要保存 K/V，所以 head 越多，KV Cache 通常越大。

现代大模型中还常见：

- **MHA**：attention heads 数量 = KV heads 数量；
- **GQA**：多个 query head 共享较少的 KV heads；
- **MQA**：多个 query head 共享 1 个 KV head。

GQA/MQA 的目的之一就是减少 KV Cache 显存占用。

一句话：

> **attention head 是 Transformer 中并行做注意力计算的一个通道；head 越多，模型看上下文的角度越多，但 KV Cache 压力也更大。**

## 4. 问题：传统的批处理方式是“静态”的：凑齐一批请求，等整个 batch 全部完成，再接收下一批。这里的 batch 什么意思？

### 复习版答案

**batch** 指的是一次送进 GPU/模型里一起计算的一组请求，中文常叫“批次 / 批处理”。

在大模型推理中：

```text
batch = [sequence A, sequence B, sequence C, ...]
```

每个 sequence 对应一个用户请求。

为什么要 batch：  
GPU 擅长并行计算，多个请求一起送入模型，可以提高 GPU 利用率和系统吞吐。

静态 batch 的问题是：  
一批请求一起开始，必须等这批里最慢的请求完成后，才处理下一批。由于不同请求输出长度不同，短请求很早结束，长请求还在生成，导致 batch 逐渐变空，GPU 利用率下降。

例如：

```text
A 生成 10 token 结束
B 生成 20 token 结束
C 生成 50 token 结束
D 生成 500 token 结束
```

静态 batch 后期可能只剩 D 在跑，GPU 没有被充分利用。

一句话：

> **batch 是一次一起送进模型计算的一组请求；静态 batch 的问题是短请求结束后位置空着，但系统仍要等最长请求完成。**

---

## 5. 问题：Continuous Batching 会影响吞吐和延迟。高并发场景下，它通常比静态 batch 更能提高吞吐。怎么理解这句？

### 复习版答案

**吞吐 throughput** 指单位时间内系统生成多少 token，常见单位是 token/s。  
**延迟 latency** 指单个用户从发出请求到得到结果需要多久，常见指标包括：

```text
TTFT：Time To First Token，首 token 延迟
TPOT：Time Per Output Token，每个输出 token 的平均时间
```

Continuous Batching 的核心是：

```text
谁结束，谁退出；
谁新来，谁补进来。
```

它不像静态 batch 那样等一整批全部完成，而是在推理过程中动态更新 batch。这样短请求结束后，新请求可以马上补进来，使 GPU 尽量保持满载。

为什么高并发下更明显：  
高并发意味着等待队列里一直有新请求。只要 batch 中有请求结束，调度器就能立刻补入新请求，减少 GPU 空转，提高整体 token/s。

但它也会影响延迟：  
因为请求进入 batch 的时机由调度器决定。为了提高整体吞吐，系统可能让某些请求等待合适的调度时机，所以单个请求的 TTFT / TPOT 可能受调度策略影响。

一句话：

> **Continuous Batching 提高吞吐，是因为它让 batch 在推理过程中持续补满；它影响延迟，是因为单个请求什么时候被调度进入 batch 由调度器决定。**

## 6. 问题：MLP 和 NLP 是什么？

### 复习版答案

**MLP = Multi-Layer Perceptron，多层感知机。**  
它是一种基础神经网络结构，通常由多层 Linear + 激活函数组成。

在 Transformer / LLM 中，MLP 通常指每个 Transformer Block 里的前馈网络部分，也叫 FFN：

```text
Transformer Block
  ├── Attention：建模 token 和 token 之间的关系
  └── MLP / FFN：对每个 token 自己的隐藏特征做非线性变换
```

**NLP = Natural Language Processing，自然语言处理。**  
它不是网络结构，而是一个 AI 研究和应用方向，目标是让机器理解、处理和生成人类语言。

NLP 任务包括：

```text
文本分类、机器翻译、情感分析、问答、摘要、聊天机器人、文本生成
```

两者关系：

```text
NLP 是应用方向
Transformer 是常用模型架构
MLP 是 Transformer 内部的一个基础模块
LLM 属于 NLP 领域的大模型
```

一句话：

> **MLP 是模型内部的计算模块；NLP 是处理自然语言的 AI 方向。**

---

## 7. 问题：HPC 是什么？

### 复习版答案

**HPC = High Performance Computing，高性能计算。**

它指的是用高性能硬件和并行计算技术，解决普通电脑算不动或算得太慢的大规模计算问题。

HPC 关键词：

```text
高算力、并行计算、CPU/GPU 集群、高速网络、大规模存储、任务调度、性能优化
```

典型应用：

```text
天气预报、航空航天仿真、分子模拟、基因计算、科学计算、大模型训练/推理
```

HPC 和 AI Infra 关系很深。大模型训练和推理都依赖：

```text
多机多卡、GPU 通信、张量并行、流水线并行、NCCL、RDMA、显存优化、算子优化
```

vLLM / nano-vLLM 虽然是推理引擎，但也体现了 HPC 思想：在有限 GPU 显存和算力下，通过调度、batch、KV Cache 管理等方式提升吞吐、降低延迟、提高资源利用率。

一句话：

> **HPC 研究如何利用多 CPU、多 GPU、集群和并行计算，把大规模计算任务高效完成。AI Infra 中的大模型训练和推理大量使用 HPC 思想。**

## 8. 问题：Prefill 结束后，系统会得到 prompt 对应的 KV Cache、最后一个位置的 logits、根据 logits 采样出的第一个输出 token。这里的 logits 是什么？

### 复习版答案

**logits** 是模型在生成下一个 token 前，对词表中每个候选 token 给出的原始分数。

它不是概率，因为：

```text
数值不一定在 0~1 之间
所有值加起来也不等于 1
```

需要经过 softmax 才会变成概率分布：

```text
logits → softmax → probability distribution → 采样/选择下一个 token
```

例如模型根据 prompt “我正在学习”预测下一个 token，会给词表里每个 token 一个分数：

```text
大模型：9.5
人工智能：8.2
vLLM：7.9
英语：2.1
```

这些分数就是 logits。经过 softmax 后，才能根据 greedy、temperature、top-k、top-p 等策略选择下一个 token。

“最后一个位置的 logits”指的是：  
Prefill 输入完整 prompt 后，模型会在每个位置都输出 logits，但真正用于生成第一个输出 token 的，是最后一个 prompt token 位置对应的 logits，因为它代表“根据完整 prompt 预测下一个 token”。

一句话：

> **KV Cache 负责保存历史上下文的中间结果；logits 负责决定下一个 token 生成什么。**
