## 1. 问题：`config_fields = {field.name for field in fields(Config)}` 这句代码中 `field` 之前未定义过也能直接来用吗？

### 复习版答案

可以。这里的 `field` 是集合推导式中的临时循环变量，由 `for field in fields(Config)` 定义，不需要提前声明。

这句等价于：

```python
config_fields = set()
for field in fields(Config):
    config_fields.add(field.name)
```

`fields(Config)` 来自 `dataclasses`，用于获取 dataclass `Config` 的字段信息；`field.name` 取每个字段的名字；最终结果是一个字段名集合，例如 `{"model", "max_model_len", "tensor_parallel_size"}`。

注意：这里的 `field` 是循环变量，不是 `dataclasses.field()` 函数。

## 2. 问题：集合推导式举例介绍语法

### 复习版答案

集合推导式用于快速生成 `set`，基本格式：

```python
{表达式 for 临时变量 in 可迭代对象 if 条件}
```

例子：

```python
nums = [1, 2, 2, 3]
unique_nums = {x for x in nums}
# {1, 2, 3}
```

集合特点：

- 自动去重；
- 无序；
- 适合保存“不重复的一组元素”。

带条件：

```python
even_squares = {x * x for x in nums if x % 2 == 0}
```

源码中的例子：

```python
config_fields = {field.name for field in fields(Config)}
```

意思是遍历 `Config` 的所有字段对象，取出字段名，组成一个不重复集合。

## 3. 问题：说一下字典的结构并举例介绍字典推导式

### 复习版答案

字典 `dict` 是 key-value 映射结构：

```python
student = {
    "name": "张三",
    "age": 20,
}
```

访问方式：

```python
student["name"]      # 张三
student.get("age")   # 20
```

核心特点：

- 用 key 查 value；
- key 必须可哈希，如 `str`、`int`、`tuple`；
- value 可以是任意对象；
- 适合表示配置项、对象属性、id 到对象的映射。

字典推导式格式：

```python
{key表达式: value表达式 for 临时变量 in 可迭代对象 if 条件}
```

例子：

```python
nums = [1, 2, 3]
square_dict = {x: x * x for x in nums}
# {1: 1, 2: 4, 3: 9}
```

源码常见用法：过滤合法配置项：

```python
valid_kwargs = {
    key: value
    for key, value in kwargs.items()
    if key in config_fields
}
```

## 4. 问题：`def __init__(self, model, **kwargs):` 类中这行代码后一个参数是什么语法，起什么作用？

### 复习版答案

`**kwargs` 用来接收任意数量的关键字参数，并把它们打包成字典。

例如调用：

```python
llm = LLM(path, enforce_eager=True, tensor_parallel_size=1)
```

进入：

```python
def __init__(self, model, **kwargs):
```

后大致变成：

```python
model = path
kwargs = {
    "enforce_eager": True,
    "tensor_parallel_size": 1,
}
```

定义函数时：

```python
def func(**kwargs):
```

表示“收集多余关键字参数”。

调用函数时：

```python
func(**kwargs)
```

表示“把字典展开成关键字参数”。

在源码中，`**kwargs` 常用于灵活接收配置项，再继续传给 `Config` 等类。

## 5. 问题：`process.start(); self.ps.append(process); self.events.append(event)` 中 `start` 和 `append` 都是什么用法？为什么没调用任何东西就可以这么用？

### 复习版答案

这三句都是“对象.方法()”调用：

```python
process.start()
self.ps.append(process)
self.events.append(event)
```

含义：

1. `process.start()`：调用 `Process` 对象的 `start()` 方法，启动子进程；
2. `self.ps.append(process)`：`self.ps` 是列表，把进程对象保存进去；
3. `self.events.append(event)`：`self.events` 是列表，把事件对象保存进去。

`start()` 来自 `Process` 类，`append()` 来自 Python 内置 `list` 类。不是“没调用”，而是方法已经由对象所属的类定义好了。

常见类似方法：

```python
list.append(x)
list.pop()
dict.get(key)
set.add(x)
process.join()
event.set()
event.wait()
```

## 6. 问题：`def generate(... ) -> list[str]:` 最后的 `-> list[str]` 是什么语法，什么意思？

### 复习版答案

`-> list[str]` 是返回值类型注解，表示这个函数设计上应该返回“字符串列表”。

例子：

```python
def add(a: int, b: int) -> int:
    return a + b
```

含义：参数 `a`、`b` 期望是 `int`，返回值期望是 `int`。

在源码中：

```python
def generate(...) -> list[str]:
```

表示 `generate` 理论上返回 `list[str]`。

但 Python 默认不会强制检查类型注解，它主要给编辑器、Pylance、mypy、读源码的人看。若源码实际返回 `[{"text": ..., "token_ids": ...}]`，程序也能运行，只是类型注解不够严谨。

## 7. 问题：`class SequenceStatus(Enum): WAITING = auto(); RUNNING = auto(); FINISHED = auto()` 中 `auto()` 什么作用？

### 复习版答案

`auto()` 来自 `enum` 模块，用于在枚举类中自动给枚举成员分配值。

```python
from enum import Enum, auto

class SequenceStatus(Enum):
    WAITING = auto()
    RUNNING = auto()
    FINISHED = auto()
```

大致等价于：

```python
WAITING = 1
RUNNING = 2
FINISHED = 3
```

但代码真正关心的是名字：

```python
seq.status = SequenceStatus.WAITING
```

而不是底层数字。

枚举适合表达有限状态，避免使用不清楚的“魔法数字”或容易拼错的字符串。在推理引擎中，`Sequence` 状态通常是：

```text
WAITING → RUNNING → FINISHED
```

## 8. 问题：`self.seq_id = next(Sequence.counter)` 举例解释语法

### 复习版答案

这句用于给当前对象分配一个递增唯一编号。

常见完整写法：

```python
from itertools import count

class Sequence:
    counter = count()

    def __init__(self):
        self.seq_id = next(Sequence.counter)
```

`Sequence.counter` 是类属性，所有 `Sequence` 对象共享；`next()` 从计数器取下一个值。

创建对象：

```python
s1 = Sequence()  # seq_id = 0
s2 = Sequence()  # seq_id = 1
s3 = Sequence()  # seq_id = 2
```

类比：`Sequence.counter` 是排号机，`next(Sequence.counter)` 是取下一张号码，`self.seq_id` 是当前请求拿到的号码。

## 9. 问题：`self.token_ids = copy(token_ids)` 介绍语法

### 复习版答案

这句表示：把传入的 `token_ids` 浅拷贝一份，保存到当前对象的 `self.token_ids` 属性里。

```python
from copy import copy
self.token_ids = copy(token_ids)
```

如果直接写：

```python
self.token_ids = token_ids
```

对象内部和外部变量会指向同一个列表，外部修改可能影响内部状态。

用 `copy(token_ids)` 后，会创建一个新的列表对象，避免外部列表修改影响当前 `Sequence`。

在 nano-vLLM 中，`token_ids` 是 prompt 编码后的 token id 列表，`Sequence` 需要保存并在后续 decode 阶段追加新 token。

## 10. 问题：`self.num_tokens = len(self.token_ids)` 和 `self.num_prompt_tokens = len(token_ids)` 什么区别？

### 复习版答案

二者初始化时通常相等，但语义不同：

```python
self.num_tokens = len(self.token_ids)
self.num_prompt_tokens = len(token_ids)
```

含义：

- `num_tokens`：当前 sequence 的总 token 数，会随着生成新 token 增长；
- `num_prompt_tokens`：初始 prompt 的 token 数，通常固定不变。

例子：

```text
prompt tokens: [10, 20, 30]
生成后完整序列: [10, 20, 30, 40, 50]
```

此时：

```python
num_prompt_tokens = 3
num_tokens = 5
num_completion_tokens = num_tokens - num_prompt_tokens = 2
```

## 11. 问题：`def __len__(self)` 和 `def __getitem__(self, key)` 这两句语法详解

### 复习版答案

它们是 Python 特殊方法，让自定义对象像容器一样使用。

```python
def __len__(self):
    return self.num_tokens
```

让对象支持：

```python
len(seq)
```

本质调用：

```python
seq.__len__()
```

---

```python
def __getitem__(self, key):
    return self.token_ids[key]
```

让对象支持：

```python
seq[0]
seq[-1]
seq[1:4]
```

本质调用：

```python
seq.__getitem__(key)
```

这让 `Sequence` 对象表现得像一个 token id 列表：能求长度、能按下标或切片访问内部 `token_ids`。

## 12. 问题：类中 `self.num_tokens` 和 `@property def num_completion_tokens` 使用方法一样吗？例如实例 `s.num_tokens` 和 `s.num_completion_tokens` 效果一样吗？

### 复习版答案

写法相似，但本质不同。

```python
self.num_tokens = len(self.token_ids)
```

这是实例属性，是真实存储在对象里的数据。

```python
@property
def num_completion_tokens(self):
    return self.num_tokens - self.num_prompt_tokens
```

这是 property 属性方法，访问时不用加括号：

```python
s.num_completion_tokens
```

但底层会自动执行函数并返回计算结果。

区别：

- `s.num_tokens`：读取对象保存的总 token 数；
- `s.num_completion_tokens`：动态计算“已生成 token 数”。

property 适合把“可由已有字段推导出的值”伪装成属性，避免重复存储导致状态不一致。

## 14. 问题：详解图中 `__getstate__` 和 `__setstate__` 代码

### 复习版答案

`__getstate__` 和 `__setstate__` 是 Python 对象序列化/反序列化相关特殊方法。

- `__getstate__`：对象被保存或跨进程传输时，决定保存哪些状态；
- `__setstate__`：对象恢复时，决定如何根据保存的状态重建对象。

图中逻辑核心：

```python
last_state = self.last_token if not self.is_prefill else self.token_ids
```

含义：

- prefill 阶段：需要完整 prompt，所以保存完整 `token_ids`；
- decode 阶段：历史信息已在 KV Cache 中，只需要最新 `last_token`。

`__getstate__` 返回一个轻量 tuple，包含 token 数、缓存数、block 表、`last_state` 等关键字段。

`__setstate__` 通过元组解包恢复字段，再判断：

```python
if isinstance(last_state, list):
```

如果是 list，说明是完整 token 序列；否则说明只是单个 last token。

核心目的：减少多进程通信时传输的数据量，符合“prefill 处理完整输入，decode 只处理最新 token + KV Cache”的推理机制。

## 15. 问题：`from collections import deque` 简要介绍 `deque` 的使用

### 复习版答案

`deque` 是双端队列，来自：

```python
from collections import deque
```

特点：两端添加和删除都很快。

常用方法：

```python
q = deque()
q.append(x)       # 右边加入
q.appendleft(x)   # 左边加入
q.pop()           # 右边弹出
q.popleft()       # 左边弹出
```

典型队列 FIFO：

```python
q.append("request1")
q.append("request2")
q.popleft()  # request1
```

典型栈 LIFO：

```python
q.append("a")
q.append("b")
q.pop()  # b
```

在推理引擎中，`deque` 常用作 waiting queue：新请求从右边进入，调度器从左边取最早请求。

## 16. 问题：简要介绍包括队列内的其它数据结构特点；deque 既可以当队列又可以当栈，其他两个还有存在必要吗？为什么 list 尾部 append 快，头部插入/删除慢；deque 两端快？

### 复习版答案

常见结构：

- `list`：动态数组，适合随机访问和尾部追加；
- `stack`：栈，后进先出 LIFO，是逻辑结构，可用 `list` 或 `deque` 实现；
- `queue`：队列，先进先出 FIFO，是逻辑结构，可用 `deque` 或 `queue.Queue` 实现；
- `deque`：双端队列，两端进出都快；
- `heapq`：堆/优先队列，按优先级取元素。

`deque` 能当栈和队列，但不能完全替代其他结构，因为：

- `list` 随机访问和切片更自然；
- `queue.Queue` 适合多线程安全通信；
- `heapq` 支持优先级调度；
- stack/queue 是抽象逻辑，deque 是具体实现之一。

为什么 `list` 头部慢？因为底层像连续数组，头部插入/删除需要整体移动元素，复杂度 `O(n)`。

为什么 `deque` 两端快？因为它的数据组织适合从两端扩展和删除，不需要整体搬移，常见两端操作接近 `O(1)`。

## 18. 问题：`def is_finished(self): return not self.waiting and not self.running` 介绍语法

### 复习版答案

这段代码用于判断调度器是否已经没有任务。

```python
def is_finished(self):
    return not self.waiting and not self.running
```

语法点：

- `self.waiting`：等待队列；
- `self.running`：正在运行的队列/列表；
- 空容器在布尔判断中为 `False`；
- `not 容器` 表示“容器是否为空”；
- `and` 表示两个条件都必须成立。

所以这句等价于：

```python
return len(self.waiting) == 0 and len(self.running) == 0
```

调度器中常用于：

```python
while not scheduler.is_finished():
    scheduler.step()
```

意思是：只要还有等待或运行中的请求，就继续调度。

## 19. 问题：`def add(self, seq: Sequence): self.waiting.append(seq)`，waiting 是双向队列，seq 是类对象，这怎么能添加？一般看到都是往队列中加数字

### 复习版答案

Python 容器不只能存数字，可以存任意对象。`deque.append(x)` 会把 `x` 作为一个整体加入队列，不关心它是数字、字符串、列表、字典还是类对象。

```python
def add(self, seq: Sequence):
    self.waiting.append(seq)
```

含义：把一个 `Sequence` 对象加入等待队列。

在推理引擎中，调度器管理的是请求对象，而不是简单数字。每个 `Sequence` 对象内部保存：

```text
seq_id
token_ids
sampling_params
status
block_table
```

所以 waiting 队列更像：

```python
deque([seq1, seq2, seq3])
```

而不是：

```python
deque([1, 2, 3])
```

这样取出队列元素后，可以直接访问和修改请求状态。

## 20. 问题：`xxhash` 计算 token block 的快速哈希，用于 prefix caching，哈希和 prefix caching 是什么意思？

### 复习版答案

哈希是把一段数据变成固定长度“指纹”的方法。

```text
token block → hash → 短指纹
```

`xxhash` 是一种很快的非加密哈希算法，适合快速判断 token block 是否已经出现过。

prefix 是“前缀”。多个请求可能有相同开头，比如相同 system prompt。

prefix caching 是：如果新请求和旧请求有相同 prompt 前缀，就复用旧请求已经计算好的 KV Cache，避免重复 prefill。

流程：

```text
1. prompt token ids 切成 block
2. 对每个 block 计算 xxhash
3. 用 hash 查缓存表
4. 命中则复用 KV Cache
5. 未命中则正常计算并写入缓存
```

为什么只复用 prefix？因为大模型 attention 的上下文位置连续，后面 token 依赖前面上下文；中间不同后，即使后面 block 内容相同，也不一定能直接复用。

一句话记忆：

```text
hash = 给 token block 做身份证
prefix caching = 相同开头不重复算
xxhash = 快速生成身份证的算法
```
