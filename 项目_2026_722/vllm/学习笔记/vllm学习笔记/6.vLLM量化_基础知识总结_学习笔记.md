---

## 0. 本节课的核心目标

这一节课的主线不是单纯介绍“量化是什么”，而是要回答一个推理系统中的核心问题：

> **为什么大模型推理需要量化？量化到底压缩了什么？它为什么可能加速，也为什么可能掉精度？vLLM 又是怎样支持这些量化模型部署的？**

在大模型推理中，GPU 显存和显存带宽经常比纯计算能力更容易成为瓶颈。以 Decoder-only LLM 为例，推理时主要有几类显存消耗：

1. **模型权重显存**：参数量越大，占用越高。例如 7B 模型使用 FP16/BF16 权重约需要 `7B × 2 bytes ≈ 14GB`，还不包含 KV Cache 和运行时开销。
2. **KV Cache 显存**：随 batch size、上下文长度、层数、head 数、head_dim 增长。
3. **激活/中间张量显存**：forward 过程中临时产生。
4. **通信与 kernel workspace**：分布式推理、量化 kernel、attention backend 可能需要额外 buffer。

量化的目的就是：

- 用更少 bit 表示权重、激活或 KV Cache；
- 降低显存占用；
- 降低显存带宽压力；
- 在硬件和 kernel 支持时提升吞吐或降低延迟；
- 让更大模型能部署到有限显存设备上。

但量化不是“无脑变小”。它本质上是在 **表示范围、表示精度、计算 kernel、硬件支持、模型精度** 之间做取舍。

---

## 1. 模型量化原理

### 1.1 什么是模型量化

模型量化就是把原来用高精度数据类型表示的张量，例如 FP32、FP16、BF16，转换成更低 bit 的表示，例如 INT8、INT4、FP8、FP4。

在 LLM 推理中，量化对象主要有三类：

| 量化对象 | 常见格式 | 作用 | 风险 |
|---|---|---|---|
| 权重 Weight | INT8、INT4、FP8、FP4 | 降低模型权重显存，占用和带宽压力 | 权重量化误差影响输出质量 |
| 激活 Activation | INT8、FP8 | 降低矩阵乘输入/输出带宽，支持 W8A8 加速 | 激活动态范围大，异常值多，量化更难 |
| KV Cache | FP8、INT8 等 | 降低长上下文和大 batch 下的 KV Cache 显存 | Attention 对 K/V 精度敏感，backend 需支持 |

量化后的模型并不是简单地把数字“截断”。更准确地说，它要建立一个从高精度实数到低精度码值的映射关系。

---

### 1.2 最基本的均匀量化公式

最常见的量化形式是 **uniform quantization（均匀量化）**。

对于一个浮点数 `x`，量化为整数 `q` 的典型公式是：

```text
q = clamp(round(x / scale) + zero_point, q_min, q_max)
```

反量化回近似浮点值：

```text
x_hat = scale × (q - zero_point)
```

其中：

- `scale`：缩放因子，决定一个整数步长对应多大的实数间隔；
- `zero_point`：零点，用于让整数空间中的某个值对应实数 0；
- `q_min, q_max`：低 bit 类型能表示的整数范围；
- `round`：把连续实数映射到离散整数；
- `clamp`：防止超出可表示范围。

例如 INT8 有 256 个离散值。如果使用有符号 INT8，一般范围为 `[-128, 127]` 或对称量化中常用 `[-127, 127]`。

---

### 1.3 对称量化与非对称量化

#### 1.3.1 对称量化

对称量化假设张量范围大致围绕 0 对称。

```text
scale = max(abs(x)) / q_max
q = round(x / scale)
x_hat = q × scale
```

特点：

- 没有 zero_point，计算简单；
- 适合权重，因为权重通常正负分布比较对称；
- 便于硬件高效实现。

#### 1.3.2 非对称量化

非对称量化适合张量分布偏移明显的情况。

```text
scale = (x_max - x_min) / (q_max - q_min)
zero_point = round(q_min - x_min / scale)
```

特点：

- 能更充分利用整数表示范围；
- 对非对称激活分布更友好；
- 计算和 kernel 实现更复杂。

---

### 1.4 量化粒度：Per-tensor、Per-channel、Group-wise、Block-wise

量化误差很大程度取决于 **scale 的粒度**。

#### 1.4.1 Per-tensor 量化

整个张量共用一个 scale。

```text
W 整个矩阵 → 一个 scale
```

优点：简单、额外元数据少。  
缺点：如果张量中有少数极大值，scale 会被这些极大值拉大，导致大多数普通值的量化精度变差。

#### 1.4.2 Per-channel 量化

按输出通道或输入通道分别使用 scale。

```text
W.shape = [out_features, in_features]
每个 out_channel 或 in_channel 有一个 scale
```

优点：精度通常明显好于 per-tensor。  
缺点：scale 数量增加，kernel 需要支持按通道缩放。

#### 1.4.3 Group-wise 量化

把通道按组划分，例如每 128 个元素一组。

```text
q_group_size = 128
每组权重共用一个 scale
```

这是 AWQ / GPTQ 等 INT4 权重量化中非常常见的方式。

优点：在精度和元数据开销之间折中。  
缺点：group size 越小，精度越好，但 scale 元数据越多，kernel 越复杂。

#### 1.4.4 Block-wise 量化

把矩阵按二维 block 或更复杂的块结构量化。FP8 block quantization、MXFP8、NVFP4 等新格式经常会涉及 block-wise 思路。

优点：适合现代 GPU tensor core / specialized kernel。  
缺点：依赖硬件和推理框架支持。

## 2. 什么是定点数和浮点数

本节目录中特别强调“定点数和浮点数”，这是理解 INT8/INT4 和 FP8/FP4 量化差异的基础。

---

### 2.1 整数表示

计算机底层只能存 bit。整数通常用固定 bit 宽表示，例如 INT8、INT16、INT32、INT64。

以 unsigned int8 为例，它有 8 个 bit，可以表示：

```text
00000000 ~ 11111111
0 ~ 255
```

signed int8 通常用补码表示，可以表示大致：

```text
-128 ~ 127
```

神经网络中的 INT8/INT4 量化并不是说模型真的只会输出整数，而是说：

> 用整数码值存储张量，再通过 scale / zero_point 解释成近似实数。

所以 INT8 量化张量一般包含两部分：

```text
整数值 q + 缩放参数 scale / zero_point
```

---

### 2.2 定点数 Fixed-point

定点数可以理解为：小数点位置固定。

例如用 8 bit 表示一个 Q4.4 定点数：

```text
4 bit 表示整数部分
4 bit 表示小数部分
```

如果底层整数值是 `q`，定点数实际值可以写成：

```text
x = q × 2^(-fraction_bits)
```

也可以更一般地写成：

```text
x = q × scale
```

从这个角度看，很多 INT8 量化都可以理解为一种“带 scale 的定点表示”。

#### 定点数优点

- 计算简单；
- 硬件实现高效；
- 适合 INT8 / INT4 矩阵乘；
- 存储紧凑。

#### 定点数缺点

- 动态范围有限；
- 对异常值敏感；
- scale 选不好会导致 clipping 或精度浪费；
- 激活量化尤其困难，因为激活分布经常有 outlier。

---

### 2.3 浮点数 Floating-point

浮点数的小数点位置不是固定的，而是通过指数位动态调整。

典型浮点数由三部分组成：

```text
sign bit + exponent bits + mantissa bits
```

可以理解为：

```text
x = (-1)^sign × mantissa × 2^exponent
```

常见格式：

| 格式 | 总 bit | 指数位 | 尾数位特点 | 典型用途 |
|---|---:|---:|---|---|
| FP32 | 32 | 8 | 精度高 | 训练、基准计算 |
| FP16 | 16 | 5 | 精度较高但范围较小 | GPU 训练/推理 |
| BF16 | 16 | 8 | 动态范围接近 FP32，尾数更少 | 大模型训练常用 |
| FP8 E4M3 | 8 | 4 | 精度相对更高，范围较小 | FP8 权重/激活 |
| FP8 E5M2 | 8 | 5 | 范围更大，精度更低 | 梯度/激活等场景 |

FP16 和 BF16 都是 16 bit，但区别很关键：

- **FP16**：尾数更多，精度比 BF16 好一点，但指数位少，动态范围小；
- **BF16**：指数位和 FP32 一样多，动态范围大，更适合训练中保持数值稳定。

---

### 2.4 定点量化与浮点量化的核心区别

| 对比项 | 定点 / 整数量化 | 浮点量化 |
|---|---|---|
| 代表格式 | INT8、INT4 | FP16、BF16、FP8、FP4 |
| 是否有指数位 | 无 | 有 |
| 动态范围 | 依赖 scale | 由 exponent 提供 |
| 精度分布 | 均匀步长 | 小数附近更密，大数附近更疏 |
| 硬件实现 | INT tensor core / custom kernel | FP tensor core / FP8 kernel |
| 适合对象 | 权重、部分激活 | 权重、激活、KV Cache |
| 常见问题 | outlier 导致 scale 失真 | 低 bit 下尾数不足、格式选择困难 |

一句话总结：

> **INT 量化更像“用少量格子均匀刻度去覆盖一个范围”；FP 量化更像“保留指数伸缩能力，但减少尾数精度”。**

## 3. 浮点量化方法的改进

课程目录中提到“浮点量化方法的改进”，可以理解为：为什么大模型推理从 FP32 到 FP16/BF16，再到 FP8/FP4，是一个逐步压缩但仍尽量保持数值稳定的过程。

---

### 3.1 从 FP32 到 FP16/BF16

早期深度学习大量使用 FP32，因为它精度高、动态范围大。但 FP32 的问题是：

- 每个参数 4 bytes，显存占用高；
- 显存带宽压力大；
- GPU tensor core 对 FP16/BF16 更友好。

所以训练和推理逐渐转向混合精度：

```text
权重 / 激活：FP16 或 BF16
部分累加：FP32 或更高精度 accumulator
```

对于 LLM，BF16 非常常见，因为它动态范围更大，训练更稳定。

---

### 3.2 从 FP16/BF16 到 FP8

FP8 进一步把每个值压缩到 1 byte。

如果模型权重从 BF16 变成 FP8：

```text
权重显存大约减半
显存带宽读取量也大约减半
```

FP8 的难点在于：

1. 只有 8 bit，精度非常有限；
2. 不同张量分布差异大；
3. E4M3 和 E5M2 适合的场景不同；
4. 需要硬件和 kernel 支持，否则可能只是省显存，不一定加速。

---

### 3.3 为什么 FP8 对 LLM 推理越来越重要

LLM 推理中最重的操作是大量 Linear / Matmul：

```text
Y = XW
```

如果 `X` 和 `W` 都能以 FP8 表示，并且硬件支持 FP8 tensor core，那么理论上可以降低：

- 权重读取带宽；
- 激活读取带宽；
- 矩阵乘计算成本；
- KV Cache 占用。

这就是 W8A8 / FP8 W8A8 的意义。

---

### 3.4 浮点量化的关键改进方向

#### 3.4.1 更细粒度 scale

即使使用 FP8，也经常需要额外 scale。原因是不同 block / channel 的数值范围不同。

常见做法：

```text
Per-tensor FP8
Per-channel FP8
Per-token FP8 activation
Block-wise FP8
```

粒度越细，精度通常越好，但元数据和 kernel 复杂度越高。

#### 3.4.2 动态量化

动态量化是在运行时根据当前输入激活统计 scale。

优点：适应不同输入分布。  
缺点：运行时需要额外统计和转换开销。

#### 3.4.3 静态量化

静态量化先用 calibration dataset 估计 scale，然后部署时固定使用。

优点：推理时开销低。  
缺点：校准数据不匹配真实请求时，精度可能下降。

#### 3.4.4 混合精度

并不是所有层都同样适合低精度。有些层更敏感，例如：

- embedding；
- lm_head；
- attention output projection；
- MoE gate；
- RMSNorm / LayerNorm 附近的张量。

所以实际部署中常见做法是：

```text
大部分 Linear 量化
少数敏感层保持 FP16/BF16
```

---

## 4. 大模型中的量化算法 AWQ

AWQ 是本节课目录中点名的大模型量化算法，需要重点掌握。

AWQ 全称是：

```text
Activation-aware Weight Quantization
```

中文可以理解为：

```text
激活感知的权重量化
```

它是一种常用于 LLM 的 **低 bit weight-only post-training quantization** 方法。

---

### 4.1 为什么 LLM 需要 AWQ 这类算法

普通 INT4 round-to-nearest 量化很容易导致精度下降。

原因是：

```text
Y = XW
```

如果某个输入通道的激活 `X[:, i]` 很大，那么对应权重列 `W[i]` 的一点点误差都会被放大，最终明显影响输出。

传统做法如果只看权重本身大小，可能会误判哪些权重重要。AWQ 的核心观察是：

> **判断哪些权重重要，不应该只看权重本身，而要看它们对应的激活分布。**

也就是说：

- 激活大的通道，对输出影响更大；
- 这些通道对应的权重量化误差更危险；
- 应该优先保护这些通道。

---

### 4.2 AWQ 的核心思想

AWQ 的核心不是把重要权重保留成 FP16，因为那会导致混合精度存储和 kernel 实现复杂。

AWQ 的做法是：

> 通过 activation statistics 找到 salient channels，然后对权重做 per-channel scaling，使重要通道在量化前被“放大”，从而降低相对量化误差；同时对激活做反向缩放，保证数学等价。

简化表达：

```text
Y = XW
```

对某个通道使用缩放 `s`：

```text
Y = (X / s) × (W × s)
```

数学上这两个表达等价：

```text
XW = (X / s)(Ws)
```

但量化时，实际是：

```text
Y_hat = (X / s) × Q(W × s)
```

由于重要权重通道被放大后再量化，相对误差会降低。

---

### 4.3 AWQ 的典型流程

AWQ 通常是 PTQ，即 Post-Training Quantization，不需要重新训练完整模型。

#### Step 1：准备校准数据

选取一批代表真实推理场景的文本，例如指令问答、代码、数学、业务数据。

#### Step 2：跑一遍 FP16/BF16 模型，收集激活统计

对每个 Linear 层输入激活 `X`，统计每个 input channel 的激活大小：

```text
s_x = mean(abs(X), dim=token/batch)
```

#### Step 3：根据激活统计识别重要通道

激活越大的通道，通常越需要保护。

#### Step 4：搜索合适的 channel scale

AWQ 会搜索或计算一个缩放因子，使量化误差尽量小。

常见形式可理解为：

```text
scale_channel = activation_stat ^ alpha
```

`alpha` 控制激活统计对缩放的影响程度。

#### Step 5：对权重做 group-wise INT4 量化

常见配置：

```text
w_bit = 4
q_group_size = 128
zero_point = True / False
```

#### Step 6：保存量化模型

保存内容包括：

- packed int4 weights；
- group scales；
- zero points；
- quantization config；
- tokenizer；
- model config。

#### Step 7：用 vLLM 加载推理

vLLM 读取量化配置，使用对应 quantization method 和 kernel 执行推理。

---

### 4.4 AWQ 为什么适合推理部署

AWQ 的优势：

1. **weight-only**：只量化权重，激活仍可用 FP16/BF16，部署稳定性更好；
2. **INT4**：权重显存大幅下降；
3. **不需要反向传播**：相比一些重构型 PTQ 方法，量化成本较低；
4. **对 instruction-tuned LLM 友好**：因为它利用激活统计保护重要通道；
5. **硬件友好**：不需要把 1% 重要权重真的保留成 FP16，而是通过缩放保持统一低 bit 格式。

AWQ 的局限：

1. 主要压缩权重，不直接压缩 KV Cache；
2. 激活仍是 FP16/BF16，所以 batch 很大或长上下文时，KV Cache 仍可能是瓶颈；
3. INT4 kernel 是否高效取决于硬件和 vLLM backend；
4. 对复杂推理、数学、代码等任务必须做精度评估；
5. 小 batch 低延迟场景可能收益明显，但高并发吞吐未必总优于 FP16/BF16，取决于 kernel 和硬件。

## 5. vLLM 中的量化支持如何理解

vLLM 的量化支持可以从三层理解：

```text
模型文件层：量化权重和 quantization_config
框架抽象层：QuantizationConfig / QuantMethod / QuantizedLinear
算子后端层：AWQ / GPTQ / Marlin / FP8 / INT8 kernel
```

---

### 5.1 模型文件层

一个量化模型通常包含：

```text
config.json
quant_config.json 或 quantize_config.json
model.safetensors
special_tokens_map.json
tokenizer.json
```

其中 `quant_config.json` 可能包含：

```json
{
  "w_bit": 4,
  "q_group_size": 128,
  "zero_point": true,
  "version": "GEMM"
}
```

vLLM 加载模型时，会读取这些信息，判断使用哪种 quantization method。

---

### 5.2 框架抽象层

在 vLLM 中，一个普通 Linear 层和一个 AWQ/GPTQ/FP8 Linear 层在逻辑上都要完成：

```text
Y = XW + b
```

但它们的权重存储和 forward kernel 不同。

可以抽象成：

```text
LinearBase
  ├── UnquantizedLinearMethod
  ├── AWQLinearMethod
  ├── GPTQLinearMethod
  ├── FP8LinearMethod
  └── INT8LinearMethod
```

当模型加载某层权重时，vLLM 会根据 quantization config：

1. 创建对应的量化参数对象；
2. 加载 packed weight；
3. 加载 scales / zero_points；
4. 在 forward 时调用对应的 quantized matmul kernel。

---

### 5.3 算子后端层

量化真正能不能加速，最终取决于 kernel。

例如 INT4 权重如果只是：

```text
先反量化成 FP16
再做普通 FP16 GEMM
```

那么可能只能省显存，不一定加速，甚至可能因为反量化开销变慢。

高性能量化 kernel 通常会做：

```text
packed INT4 weight 读取
↓
在 kernel 内解包 / 反量化
↓
与 FP16/BF16 activation 做矩阵乘
↓
输出 FP16/BF16
```

对于 W8A8 / FP8，则可能直接走硬件支持的低精度 tensor core。

---

### 5.4 vLLM 中常见量化格式

| 格式 | 含义 | 典型场景 |
|---|---|---|
| AWQ | Activation-aware INT4 weight-only | 显存有限，想部署 INT4 LLM |
| GPTQ | 基于近似二阶误差补偿的 weight-only PTQ | INT4 权重量化，精度通常较好 |
| FP8 W8A8 | 权重和激活都用 FP8 | Ada/Hopper/更新 GPU 上高性能推理 |
| INT8 W8A8 | 权重和激活 INT8 | 硬件支持 INT8 时用于加速和省显存 |
| BitsAndBytes | 常见 4bit/8bit 在线加载量化 | 快速试验、显存不足场景 |
| KV Cache Quantization | KV Cache 使用 FP8 等低精度 | 长上下文、大 batch 场景 |

---

## 6. 训练、量化、推理的完整流程

### 6.1 训练阶段

大模型训练通常使用 FP32、FP16、BF16 或混合精度。

训练目标是得到高质量权重：

```text
语料 → tokenizer → token ids → Transformer forward → loss → backward → optimizer update
```

训练结束后保存 checkpoint：

```text
BF16 / FP16 checkpoint
```

---

### 6.2 离线量化阶段

如果使用 AWQ / GPTQ / SmoothQuant / FP8 PTQ，通常需要单独的量化阶段。

```text
加载 FP16/BF16 模型
↓
准备校准数据
↓
收集激活统计
↓
计算 scale / zero_point / group scale
↓
量化权重或激活相关参数
↓
保存量化 checkpoint
↓
评估精度
```

精度评估不能只看模型能否跑通，至少要看：

- perplexity；
- MMLU / C-Eval / GSM8K / HumanEval 等 benchmark；
- 业务自有评测集；
- 长文本稳定性；
- 工具调用 / JSON 输出稳定性；
- 多轮对话一致性。

---

### 6.3 vLLM 推理部署阶段

典型路径：

```text
量化模型 checkpoint
↓
vLLM 加载模型
↓
读取 quantization_config
↓
构建 QuantizedLinear / QuantMethod
↓
分配 KV Cache
↓
接收请求
↓
Prefill
↓
Decode
↓

↓

```

如果是 AWQ 模型，逻辑上：

```text
用户请求 token ids
↓
Embedding
↓
Transformer block
  ↓
  Quantized Linear: packed INT4 weight + FP16 activation
  ↓
  Attention / MLP
↓
LM Head
↓
logits
↓
sampling
```

## 7. 量化如何影响 Prefill 和 Decode

### 7.1 Prefill 阶段

Prefill 一次处理 prompt 中所有 token。

特点：

- batch 内 token 数较多；
- GEMM 规模较大；
- 更偏计算密集；
- 量化可以减少权重读取，也可能提升矩阵乘性能。

### 7.2 Decode 阶段

Decode 每轮通常每个请求生成 1 个 token。

特点：

- 每步 token 少；
- 需要反复读取模型权重；
- 更容易受显存带宽限制；
- weight-only quantization 对 decode 帮助通常更直观，因为权重读取量下降。

所以面试中可以这样回答：

> 量化对 Decode 阶段通常很重要，因为 Decode 是逐 token 自回归，每一步都要读大量权重，容易受显存带宽限制；降低权重 bit 数可以减少带宽压力。但最终是否加速，还取决于量化 kernel 是否高效，以及 batch size、硬件 tensor core 支持等因素。

---

## 8. 常见量化方案对比

| 方案 | 权重 | 激活 | KV Cache | 显存节省 | 加速潜力 | 精度风险 | 适合场景 |
|---|---|---|---|---|---|---|---|
| FP16/BF16 | 16 bit | 16 bit | 16 bit | 低 | 稳定 | 低 | 默认高质量部署 |
| INT8 W8A8 | INT8 | INT8 | 通常不变 | 中 | 高，需硬件支持 | 中 | GPU 支持 INT8 kernel |
| FP8 W8A8 | FP8 | FP8 | 可选 FP8 | 中高 | 高，尤其新 GPU | 中 | Ada/Hopper/Blackwell 等新硬件 |
| AWQ W4A16 | INT4 | FP16/BF16 | 不变 | 高 | 中到高，取决于 kernel | 中 | 显存紧张、低延迟部署 |
| GPTQ W4A16 | INT4 | FP16/BF16 | 不变 | 高 | 中到高 | 中 | 权重量化精度优先 |
| KV Cache FP8 | 不一定 | 不一定 | FP8 | 长上下文收益高 | 间接提升并发 | 中 | 长上下文、大 batch |

## 9. 量化部署时最容易踩的坑

### 9.1 误以为量化一定加速

量化一定能减少显存吗？通常是。  
量化一定能加速吗？不一定。

原因：

- kernel 不够优化；
- 反量化开销太大；
- batch 太小或太大时瓶颈变化；
- attention / sampling / 通信成为瓶颈；
- 硬件不支持对应低精度 tensor core。

---

### 9.2 只看模型权重显存，不看 KV Cache

INT4 AWQ 可以大幅降低权重显存，但长上下文服务中 KV Cache 可能成为主要显存消耗。

此时要考虑：

- max_model_len；
- max_num_seqs；
- gpu_memory_utilization；
- KV Cache dtype；
- prefix caching；
- chunked prefill；
- tensor parallel / pipeline parallel。

---

### 9.3 校准数据和真实业务不匹配

AWQ、GPTQ、SmoothQuant 等 PTQ 方法都依赖 calibration data。

如果校准数据是英文通用问答，但线上是中文代码生成或 JSON 工具调用，量化后可能出现：

- 格式遵循能力下降；
- 代码正确率下降；
- 数学推理下降；
- 长文本输出不稳定。

---

### 9.4 忽略硬件支持

同一个量化模型在不同 GPU 上表现可能完全不同。

例如：

- 老 GPU 可能不支持 FP8 tensor core；
- 某些 INT4 kernel 只对特定架构优化；
- AMD / Intel / CPU 后端支持情况不同；
- Blackwell 等新硬件可能推荐 FP8/FP4 路线，而不是传统 INT8。

---

## 10. 面试重点总结

### 10.1 一句话解释量化

> 量化是把模型中的高精度浮点张量映射到低 bit 表示，通过 scale、zero point 或低精度浮点格式近似原始数值，从而降低显存占用和带宽压力；在硬件和 kernel 支持时，还可以提升推理吞吐或降低延迟。

### 10.2 一句话解释 AWQ

> AWQ 是一种激活感知的 INT4 weight-only PTQ 方法，它通过校准数据统计激活分布，识别对输出影响更大的权重通道，并通过 per-channel scaling 保护这些重要通道，从而在保持硬件友好的统一低 bit 权重格式下减少量化误差。

### 10.3 一句话解释 W4A16

> W4A16 表示权重用 4 bit 存储和计算路径中的量化权重格式，激活仍用 16 bit；它主要减少权重显存和权重读取带宽，但不直接压缩激活或 KV Cache。

### 10.4 一句话解释 W8A8

> W8A8 表示权重和激活都使用 8 bit，理论上比 weight-only 更可能带来计算加速，但对激活量化、scale 选择、硬件 tensor core 和 kernel 支持要求更高。

## 11. 面试问题与参考答案

### Q1：为什么大模型推理需要量化？

答：大模型推理的主要瓶颈之一是显存容量和显存带宽。模型权重以 FP16/BF16 存储时，每个参数需要 2 bytes，几十 B 或上百 B 参数模型会占用大量显存。Decode 阶段逐 token 生成，每一步都要读取大量权重，容易受带宽限制。量化通过 INT8、INT4、FP8 等低 bit 表示减少权重、激活或 KV Cache 的存储和读取量，从而降低显存占用，并在硬件和 kernel 支持时提升吞吐。

---

### Q2：量化一定会让推理更快吗？

答：不一定。量化通常会减少显存占用，但是否加速取决于 kernel 和硬件支持。如果量化权重需要先反量化成 FP16 再计算，反量化开销可能抵消收益。只有当 packed weight 读取、低精度 matmul、scale 处理等都在高效 kernel 中完成，且瓶颈确实在权重带宽或低精度计算时，量化才会明显加速。

---

### Q3：对称量化和非对称量化有什么区别？

答：对称量化没有 zero point，通常把 0 放在整数范围中心，公式是 `q = round(x / scale)`，适合分布接近 0 对称的权重。非对称量化有 zero point，可以更好覆盖非对称分布，公式是 `q = round(x / scale) + zero_point`，适合偏移明显的激活，但实现更复杂。

---

### Q4：Per-tensor、Per-channel 和 Group-wise 量化有什么区别？

答：Per-tensor 是整个张量共用一个 scale，简单但容易受 outlier 影响。Per-channel 是每个通道一个 scale，精度更好但元数据更多。Group-wise 是每组通道或每组元素共用一个 scale，是 INT4 LLM 权重量化中常见折中方案，例如 AWQ 常见 group size 为 128。

---

### Q5：为什么激活量化比权重量化更难？

答：权重是固定的，离线可以完整统计分布并优化 scale；激活依赖输入请求，动态范围变化大，而且 LLM 激活中经常存在 outlier。如果激活 outlier 拉大 scale，大多数普通值的量化分辨率会下降；如果 scale 太小，又会 clipping。所以 W8A8 通常比 W4A16 更难保持精度。

---

### Q6：AWQ 的核心思想是什么？

答：AWQ 认为不是所有权重同等重要，权重的重要性应该根据对应输入激活来判断。如果某个输入通道激活大，那么该通道权重量化误差会被放大。AWQ 通过校准数据统计激活，找到 salient channels，并对这些通道做 scaling，使权重在量化前被放大，降低相对量化误差，同时对激活做反向缩放保持数学等价。

---

### Q7：AWQ 为什么不直接把重要权重保留为 FP16？

答：直接保留部分权重为 FP16 会变成混合精度存储和计算，kernel 实现复杂，硬件效率差。AWQ 通过 per-channel scaling 保护重要通道，让所有权重仍保持统一 INT4 格式，更适合 packed weight 和高性能 kernel。

---

### Q8：AWQ 和 GPTQ 有什么区别？

答：AWQ 是 activation-aware，通过激活统计识别重要通道并做 scaling，强调不依赖反向传播或复杂重构。GPTQ 更强调逐层近似二阶误差补偿，使用 Hessian 近似思想减少量化后输出误差。两者都常用于 weight-only INT4 PTQ，但优化目标和算法路径不同。

---

### Q9：W4A16、W8A8 分别是什么意思？

答：W4A16 表示 weight 4 bit、activation 16 bit，典型如 AWQ/GPTQ INT4 weight-only。它主要压缩权重。W8A8 表示 weight 和 activation 都是 8 bit，例如 INT8 W8A8 或 FP8 W8A8，它既压缩权重也压缩激活，更可能利用低精度 tensor core，但精度和 kernel 要求更高。

---

### Q10：量化和 KV Cache 有什么关系？

答：权重量化只减少模型参数显存，不会减少 KV Cache。长上下文和高并发场景中，KV Cache 可能成为主要显存瓶颈。此时需要考虑 KV Cache quantization，例如 FP8 KV Cache，或者通过 PagedAttention、prefix caching、chunked prefill 等方式提高 KV Cache 管理效率。

---

### Q11：为什么 Decode 阶段特别受益于 weight-only 量化？

答：Decode 每一步通常每个请求只生成一个 token，矩阵乘规模较小，但每步都要读取完整模型权重，因此容易受显存带宽限制。weight-only 量化把权重从 FP16/BF16 压到 INT4/INT8，可以显著减少权重读取量，所以对 Decode 阶段有潜在收益。

---

### Q12：vLLM 支持量化时主要做了哪些事情？

答：vLLM 首先读取模型的 quantization config，判断量化类型；然后在模型构建时把普通 Linear 替换为对应的 QuantizedLinear 或 QuantMethod；加载 packed weights、scales、zero points 等量化参数；最后在 forward 中调用对应的量化 kernel，例如 AWQ/GPTQ/FP8/INT8 后端。

---

### Q13：如何判断一个量化模型是否适合上线？

答：不能只看能否跑通和显存降低。需要同时评估：模型精度、业务任务指标、格式遵循能力、长上下文稳定性、吞吐、TTFT、TPOT、显存占用、并发扩展性、硬件兼容性。如果是聊天和工具调用，还要重点测 JSON 输出、function call、中文任务和多轮对话。

---

## 12. 学习路线建议

如果你是为了 AI Infra 实习面试，建议按以下顺序学习本节内容：

1. 先搞懂 `scale / zero_point / qmin / qmax` 公式；
2. 再搞懂 INT8、INT4、FP16、BF16、FP8 的表示差异；
3. 理解 W4A16、W8A8、KV Cache quantization 分别量化了什么；
4. 重点掌握 AWQ 的 activation-aware 思想；
5. 能讲清 vLLM 中量化模型加载到 QuantizedLinear forward 的链路；
6. 最后结合 benchmark 分析量化对显存、TTFT、TPOT、吞吐的影响。

## 13. 本节课最终总结

本节课的主线可以总结为：

```text
大模型太大
↓
FP16/BF16 权重和 KV Cache 占用大量显存
↓
推理尤其 Decode 阶段容易受显存带宽限制
↓
量化用低 bit 表示权重、激活或 KV Cache
↓
定点/整数量化依赖 scale 和 zero_point
↓
浮点量化依赖 sign/exponent/mantissa，FP8/FP4 保留动态范围能力
↓
普通低 bit 量化会带来误差
↓
AWQ 用激活统计识别重要权重通道并缩放保护
↓
vLLM 通过 quantization config、QuantMethod 和量化 kernel 加载并执行量化模型
↓
最终实现更低显存、更高部署灵活性，并在合适硬件上获得推理加速
```

对于面试，最重要的不是背诵“AWQ 是什么”，而是能把它放回推理系统中解释：

> **量化解决的是权重、激活、KV Cache 的存储和带宽问题；AWQ 是一种在 INT4 weight-only 量化中尽量降低精度损失的方法；vLLM 的价值在于把这些量化权重接入高性能推理框架和 kernel 后端，让它真正能服务在线推理。**
