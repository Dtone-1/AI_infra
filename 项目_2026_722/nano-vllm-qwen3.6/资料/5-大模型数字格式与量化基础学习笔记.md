## 一、这节课的核心宗旨

这节课主要讲的是：

**大模型中常见数字格式的底层表示方式，以及为什么理解这些格式是学习模型量化的基础。**

大模型本质上并不是直接处理“文字”，而是在处理数字：

1. 输入文本经过 tokenizer 变成 token id；
2. token id 经过 embedding 变成向量；
3. 模型参数本身是大量数字；
4. 前向计算中的激活值也是数字；
5. 输出 logits 也是数字；
6. 最终 token id 再 decode 成人类能读的文本。

所以，大模型训练和推理中的核心问题之一就是：

**这些数字用什么格式存？用多少 bit 存？计算时用什么精度？会不会溢出？会不会精度不够？能不能用更低 bit 降低显存和加速推理？**

课程主要介绍了几类常见数字格式：

| 类型 | 常见格式 | 主要用途 |
|---|---|---|
| 浮点数 | FP32、FP16、BF16、FP8 | 训练、推理、混合精度、低精度计算 |
| 整数 | INT8、INT4 | 量化推理、权重量化、KV Cache 量化 |

一句话总结：

**数字格式决定了一个数能表示多大、表示多精细、占多少显存、适合什么硬件计算；理解 FP32/FP16/BF16/FP8/INT8/INT4，是理解大模型量化和推理优化的前置基础。**

---

## 二、为什么 AI Infra 必须理解数字格式

如果只从算法公式看，大模型计算似乎就是矩阵乘法：

```text
Y = XW
Attention = softmax(QK^T / sqrt(d_k))V
MLP = activation(XW_1)W_2
```

但在真实推理系统中，每个矩阵里的元素都要用某种数字格式存储。

例如一个 7B 参数模型，如果每个参数用 FP16 存：

```text
7B 参数 x 2 bytes = 14GB
```

如果用 INT8 存：

```text
7B 参数 x 1 byte = 7GB
```

如果用 INT4 存：

```text
7B 参数 x 0.5 byte = 3.5GB
```

这直接影响：

1. 模型能不能放进单卡显存；
2. 推理时显存带宽压力有多大；
3. batch size 能开多大；
4. KV Cache 能存多少 token；
5. prefill 和 decode 的吞吐；
6. 量化后精度会不会明显下降。

所以数字格式不是孤立的基础知识，而是 AI Infra 推理优化的核心之一。

## 三、课程按时间推进梳理知识点

### 1. 大模型为什么离不开数字

课程一开始强调，理解数字格式的原因是：大模型的输入、参数、计算和输出，本质上都是数字。

以语言模型为例：

```text
文本
  ↓ tokenizer
token id
  ↓ embedding
向量
  ↓ Transformer 层计算
hidden states
  ↓ lm head
logits
  ↓ sampling
output token id
  ↓ decode
文本输出
```

其中：

1. token id 是整数；
2. embedding 是浮点数矩阵；
3. Transformer 权重是浮点数或量化整数；
4. hidden states 是浮点数；
5. logits 是浮点数；
6. KV Cache 也通常用 FP16/BF16/FP8 等格式存储。

因此，数字格式决定了大模型在硬件上如何存储和计算。

---

### 2. 浮点数 FP 的含义

课程接着介绍 FP 类型。

```text
FP = Floating Point
```

也就是浮点数。

浮点数可以用来表示小数，也可以表示很大或很小的数。

大模型中常见的浮点格式包括：

| 格式 | 总 bit 数 |
|---|---:|
| FP32 | 32 bit |
| FP16 | 16 bit |
| BF16 | 16 bit |
| FP8 | 8 bit |

这些格式的共同点是，它们都大致由三部分组成：

```text
符号位 sign
指数位 exponent
小数位 fraction / mantissa
```

浮点数的核心思想是类似科学计数法：

```text
数值 = 符号 x 有效数字 x 底数^指数
```

二进制浮点数中，底数是 2。

---

### 3. 例子：13.25 如何转成二进制

课程用 `13.25` 举例。

先看整数部分：

```text
13 = 8 + 4 + 1
   = 2^3 + 2^2 + 2^0
```

所以：

```text
13 的二进制 = 1101
```

再看小数部分：

```text
0.25 = 1/4 = 2^-2
```

所以：

```text
0.25 的二进制 = 0.01
```

合起来：

```text
13.25 = 1101.01_2
```

---

### 4. 二进制科学计数法

类似十进制科学计数法：

```text
13.5 = 1.35 x 10^1
```

二进制也可以写成规范化形式：

```text
1101.01_2 = 1.10101_2 x 2^3
```

这里可以拆成三部分：

| 部分 | 对应内容 |
|---|---|
| 符号 | 正数，所以 sign = 0 |
| 有效数字 | `1.10101` |
| 指数 | `3` |

对于规范化二进制浮点数，最高位通常一定是 `1`。

所以这个最高位 `1` 可以不存，默认存在。

真正存储的小数位是：

```text
10101...
```

这就是 fraction / mantissa 部分。

---

### 5. FP32 的基本结构

FP32 一共 32 bit，通常划分为：

| 部分 | bit 数 |
|---|---:|
| sign | 1 bit |
| exponent | 8 bit |
| fraction | 23 bit |

也就是：

```text
FP32 = 1 sign bit + 8 exponent bits + 23 fraction bits
```

对于正数，sign = 0。

对于负数，sign = 1。

刚才的 `13.25` 是正数，所以：

```text
sign = 0
```

fraction 部分存：

```text
10101000000000000000000
```

也就是把 `1.10101` 中隐藏的最高位 `1` 去掉，只保存后面的 `10101`，剩余位置补 0。

---

### 6. 指数位为什么要用 bias

指数有正有负，例如：

```text
2^3
2^-3
```

但是 exponent 字段本身是无符号 bit，如果直接存，会不好表达负指数。

所以浮点数使用 bias：

```text
stored_exponent = real_exponent + bias
```

对于 FP32：

```text
bias = 127
```

因为 FP32 的 exponent 有 8 bit，通常：

```text
bias = 2^(8 - 1) - 1 = 127
```

对于 `13.25`：

```text
real_exponent = 3
stored_exponent = 3 + 127 = 130
```

130 的二进制是：

```text
10000010
```

所以 `13.25` 的 FP32 存储可以理解为：

```text
sign      exponent   fraction
0         10000010   10101000000000000000000
```

---

### 7. FP32 正规数的计算公式

对于普通正规数，FP32 的值可以写成：

```text
value = (-1)^sign x (1 + fraction) x 2^(exponent - bias)
```

其中：

1. `sign` 决定正负；
2. `fraction` 是小数位代表的二进制小数；
3. `exponent` 是实际存储的指数；
4. `bias` 是指数偏置；
5. `1 + fraction` 里的 `1` 是隐藏位。

以 `13.25` 为例：

```text
sign = 0
stored_exponent = 130
bias = 127
real_exponent = 3
fraction = 0.10101_2
```

所以：

```text
value = (+1) x 1.10101_2 x 2^3
      = 1101.01_2
      = 13.25
```

---

### 8. FP32 的特殊情况：0、非正规数、无穷、NaN

课程还提到 exponent 的特殊取值。

FP32 的 exponent 有 8 bit，所以存储值范围是：

```text
0 ~ 255
```

但并不是所有值都按普通正规数公式解释。

| exponent | fraction | 含义 |
|---|---|---|
| 1 ~ 254 | 任意 | 正规数 |
| 0 | 0 | +0 或 -0 |
| 0 | 非 0 | 非正规数 subnormal |
| 255 | 0 | +∞ 或 -∞ |
| 255 | 非 0 | NaN |

其中：

```text
NaN = Not a Number
```

表示非法或未定义的数值，例如某些无效计算结果。

---

### 9. 非正规数的作用

正规数能表示的最小正数和 0 之间仍然有一段空隙。

如果没有非正规数，一些非常小的数可能会突然下溢成 0。

非正规数的作用就是：

**用更低精度填补正规数最小值和 0 之间的区域，让数值可以更平滑地接近 0。**

非正规数不再使用隐藏的最高位 `1`，而是类似：

```text
value = (-1)^sign x (0 + fraction) x 2^(最小指数)
```

这让它可以表示比最小正规数还小的数。

在大模型训练中，这和数值稳定性有关。

---

### 10. FP16 的结构

FP16 一共 16 bit：

| 部分 | bit 数 |
|---|---:|
| sign | 1 bit |
| exponent | 5 bit |
| fraction | 10 bit |

也就是：

```text
FP16 = 1 sign bit + 5 exponent bits + 10 fraction bits
```

FP16 的 exponent bias 是：

```text
bias = 2^(5 - 1) - 1 = 15
```

相比 FP32，FP16 的特点是：

1. 总 bit 数少，占用显存更小；
2. fraction 位更少，精度更低；
3. exponent 位更少，表示范围更小；
4. 更容易出现 overflow 或 underflow；
5. 但硬件通常支持 FP16 Tensor Core 加速。

---

### 11. BF16 的结构

BF16 也是 16 bit，但它和 FP16 的位数分配不同。

BF16 结构是：

| 部分 | bit 数 |
|---|---:|
| sign | 1 bit |
| exponent | 8 bit |
| fraction | 7 bit |

也就是：

```text
BF16 = 1 sign bit + 8 exponent bits + 7 fraction bits
```

BF16 的 exponent 和 FP32 一样是 8 bit，所以它的数值范围接近 FP32。

但它的 fraction 只有 7 bit，所以精度比 FP16 更粗。

可以这样理解：

| 格式 | 范围 | 精度 |
|---|---|---|
| FP16 | 范围较小 | 精度相对 BF16 更高 |
| BF16 | 范围接近 FP32 | 精度较低 |

BF16 在大模型训练中很常见，因为训练中数值范围很重要。如果范围太小，容易溢出或下溢。

---

### 12. FP16 和 BF16 的区别

FP16 和 BF16 都是 16 bit，但侧重点不同。

| 格式 | sign | exponent | fraction | 特点 |
|---|---:|---:|---:|---|
| FP16 | 1 | 5 | 10 | 精度相对更高，但范围更小 |
| BF16 | 1 | 8 | 7 | 范围更大，但精度更低 |

在大模型中：

1. FP16 常用于推理和混合精度训练；
2. BF16 常用于训练，因为更不容易 overflow；
3. 两者都比 FP32 节省一半显存；
4. 两者都可以提高 Tensor Core 利用率。

面试中经常会问：

**为什么大模型训练常用 BF16？**

核心回答：

**BF16 保留了和 FP32 一样的 8 位指数，因此动态范围大，训练时更稳定；虽然尾数精度低，但深度学习通常能容忍一定精度损失。**

---

### 13. FP8 的结构

课程提到 FP8。

FP8 一共只有 8 bit，常见格式包括：

```text
E4M3
E5M2
```

其中：

1. `E` 表示 exponent bits；
2. `M` 表示 mantissa / fraction bits。

常见结构可以理解为：

| 格式 | sign | exponent | mantissa | 特点 |
|---|---:|---:|---:|---|
| E4M3 | 1 | 4 | 3 | 精度稍高，范围较小 |
| E5M2 | 1 | 5 | 2 | 范围更大，精度更低 |

注意：不同硬件和框架中，FP8 的具体特殊值规则可能略有差异，例如 NVIDIA 常见 E4M3FN 和 E5M2。

对于学习主线来说，重点是：

**FP8 通过更少的 bit 降低显存占用和内存带宽压力，但由于 exponent 和 mantissa 都很少，因此更依赖量化策略、缩放因子和硬件支持。**

---

### 14. 浮点格式的本质：范围和精度的权衡

浮点数格式最核心的权衡是：

```text
exponent 位数决定范围
mantissa 位数决定精度
```

更大的 exponent：

1. 能表示更大或更小的数；
2. 动态范围更大；
3. 更不容易 overflow / underflow。

更多的 mantissa：

1. 小数更精细；
2. 舍入误差更小；
3. 表示精度更高。

所以：

| 格式 | 动态范围 | 精度 | 显存占用 |
|---|---|---|---|
| FP32 | 大 | 高 | 高 |
| FP16 | 较小 | 中等 | 中 |
| BF16 | 大 | 较低 | 中 |
| FP8 | 取决于格式 | 低 | 低 |

---

### 15. INT8 的含义

课程接着讲 INT8。

```text
INT8 = 8 bit signed integer
```

它是有符号 8 位整数。

8 bit 一共有：

```text
2^8 = 256
```

种状态。

对于有符号 INT8，通常表示范围是：

```text
-128 ~ 127
```

它不是浮点数，没有 exponent 和 mantissa。

整数格式的特点是：

1. 存储简单；
2. 占用小；
3. 计算快；
4. 但不能直接表示小数；
5. 需要通过 scale / zero point 等量化参数把浮点数映射到整数。

---

### 16. 补码：负数如何用二进制表示

课程用 INT8 解释补码。

对于正数，二进制很好理解：

```text
+1 = 00000001
+2 = 00000010
```

对于负数，计算机通常用补码表示。

求 `-1` 的 INT8 补码：

1. 先写出 `+1`：

```text
00000001
```

2. 按位取反：

```text
11111110
```

3. 加 1：

```text
11111111
```

所以：

```text
-1 = 11111111
```

求 `-2`：

```text
+2 = 00000010
取反 = 11111101
加 1 = 11111110
```

所以：

```text
-2 = 11111110
```

---

### 17. 补码为什么有用

补码的好处是：

**可以把减法统一成加法。**

例如：

```text
1 + (-1)
```

用 INT8 补码：

```text
00000001
+11111111
=1 00000000
```

由于 INT8 只能保留 8 bit，最左边溢出的 `1` 被丢弃，结果是：

```text
00000000
```

也就是 0。

这说明补码让硬件可以用同一套加法电路处理加法和减法。

---

### 18. INT4 的含义

INT4 是 4 bit 整数。

如果是有符号 INT4，通常范围是：

```text
-8 ~ 7
```

INT4 比 INT8 更省显存。

例如：

| 格式 | 每个参数占用 |
|---|---:|
| FP16 | 16 bit = 2 bytes |
| INT8 | 8 bit = 1 byte |
| INT4 | 4 bit = 0.5 byte |

所以 INT4 权重量化可以显著降低模型权重显存。

但是 INT4 表示能力更弱，量化误差也更大，所以通常需要更精细的量化算法，例如 group-wise quantization、AWQ、GPTQ 等。

## 四、从输入到输出串联完整流程

这节课虽然主要讲数字格式，但可以和大模型推理流程串起来。

### 1. 输入文本先变成整数 token id

用户输入：

```text
你好，请介绍一下 vLLM
```

经过 tokenizer：

```text
[token_id_1, token_id_2, token_id_3, ...]
```

这些 token id 本质上是整数。

---

### 2. token id 经过 embedding 变成浮点向量

模型会用 token id 查 embedding 表：

```text
X = embedding[token_ids]
```

embedding 表中的参数通常是 FP16、BF16、FP32 或量化格式。

得到的 `X` 是浮点向量。

---

### 3. Transformer 层中大量矩阵乘法依赖数字格式

在每一层 Transformer 中，会计算：

```text
QKV = XW_QKV
Attention = softmax(QK^T / sqrt(d_k))V
MLP = activation(XW_1)W_2
```

其中：

1. 权重 `W` 有自己的存储格式；
2. 激活 `X` 有自己的计算格式；
3. KV Cache 有自己的存储格式；
4. 矩阵乘法可能用 FP16/BF16/FP8/INT8 等硬件路径。

---

### 4. 输出 logits 也是浮点数

最后一层会通过 LM Head 得到 logits：

```text
logits = hidden_states W_vocab
```

logits 是每个词表 token 对应的分数，通常是浮点数。

然后 sampling 根据 logits 选择下一个 token。

---

### 5. 数字格式影响整个推理系统

从输入到输出，每一步都和数字格式有关：

```text
token id: 整数
embedding: 浮点或量化权重
attention weight: 浮点或量化权重
activation: FP16/BF16/FP8 等
KV Cache: FP16/BF16/FP8/INT8 等
MLP weight: FP16/BF16/INT8/INT4 等
logits: 通常浮点
```

所以量化不是孤立地“把模型变小”，而是改变了整个推理过程中的数据表示和计算路径。

---

## 五、与 AI Infra / 推理系统的关系

### 1. 数字格式直接影响显存

模型权重显存大致是：

```text
参数量 x 每个参数字节数
```

例如 7B 参数：

| 格式 | 每参数字节 | 权重显存约 |
|---|---:|---:|
| FP32 | 4 bytes | 28 GB |
| FP16/BF16 | 2 bytes | 14 GB |
| INT8 | 1 byte | 7 GB |
| INT4 | 0.5 byte | 3.5 GB |

这就是为什么量化能让更大的模型放进更小显存。

---

### 2. 数字格式影响显存带宽

推理时不只是“能不能放下”，还要考虑“读得快不快”。

Decode 阶段经常受显存带宽限制。

如果权重或 KV Cache 用更低 bit 存储，那么从 HBM 读取的数据量会减少。

这可能提升吞吐，尤其在 memory-bound 场景下很重要。

---

### 3. 数字格式影响 Tensor Core 路径

现代 GPU 对不同数字格式有不同硬件加速能力。

例如：

1. FP16/BF16 通常有成熟 Tensor Core 支持；
2. FP8 在 H100 等新硬件上有更强支持；
3. INT8 也有专门的整数矩阵乘法加速；
4. INT4 是否高效取决于硬件和 kernel 实现。

所以选择数字格式不只是模型精度问题，也是硬件适配问题。

---

### 4. 数字格式与量化算法的关系

量化的核心就是把高精度数字映射成低精度数字。

例如把 FP16 权重映射成 INT8：

```text
float_weight -> int8_weight + scale
```

推理时再近似还原：

```text
float_value ≈ scale x int_value
```

如果是 INT4：

```text
float_weight -> int4_weight + scale
```

误差更大，所以通常需要更好的分组策略和校准方法。

理解 FP 和 INT 的底层表示，才能理解后续的：

1. weight-only quantization；
2. activation quantization；
3. KV Cache quantization；
4. per-tensor quantization；
5. per-channel quantization；
6. group-wise quantization；
7. GPTQ / AWQ / SmoothQuant。

---

### 5. FP8 与 KV Cache 量化

在推理系统中，KV Cache 会随着：

```text
batch size x sequence length x layer number
```

增长。

长上下文、多并发请求时，KV Cache 可能占用大量显存。

如果把 KV Cache 从 FP16 降到 FP8：

```text
每个元素从 2 bytes 降到 1 byte
```

理论上 KV Cache 显存可以接近减半。

但这需要考虑：

1. 精度损失；
2. scale 如何保存；
3. attention kernel 是否支持 FP8 KV；
4. dequant 是否带来额外开销；
5. 对 TPOT 和吞吐是否真的有收益。

这和你后面做 nano-vLLM 的 FP8 KV Cache 项目非常相关。

---

|---|---:|---:|---:|---:|---|---|---|
| FP32 | 32 | 1 | 8 | 23 | 高精度训练、累加、参考实现 | 范围大、精度高 | 显存大、速度慢 |
| FP16 | 16 | 1 | 5 | 10 | 混合精度、推理 | 省显存、Tensor Core 快 | 范围小，容易溢出 |
| BF16 | 16 | 1 | 8 | 7 | 大模型训练 | 范围接近 FP32，训练稳定 | 精度比 FP16 粗 |
| FP8 E4M3 | 8 | 1 | 4 | 3 | FP8 训练/推理 | 比 E5M2 精度稍好 | 范围较小 |
| FP8 E5M2 | 8 | 1 | 5 | 2 | FP8 训练/推理 | 范围更大 | 精度更低 |
| INT8 | 8 | 补码 | 无 | 无 | 量化推理 | 显存小、硬件支持较多 | 需要 scale，精度有损 |
| INT4 | 4 | 补码 | 无 | 无 | 权重量化 | 权重显存极小 | 误差更大，kernel 更复杂 |

## 七、面试常见问题与回答

### 1. 为什么大模型需要了解数字格式？

因为大模型的参数、激活、KV Cache、logits 本质上都是数字。

数字格式决定了它们占多少显存、能表示多大范围、精度有多高、能否被硬件高效计算。量化、混合精度训练、FP8 KV Cache 等优化都建立在数字格式之上。

---

### 2. FP32 由哪几部分组成？

FP32 一共 32 bit：

```text
1 bit sign
8 bit exponent
23 bit fraction
```

它通过符号位、指数位和小数位共同表示一个浮点数。

正规数公式是：

```text
value = (-1)^sign x (1 + fraction) x 2^(exponent - bias)
```

FP32 的 bias 是 127。

---

### 3. 浮点数中的 exponent 和 mantissa 分别决定什么？

exponent 决定动态范围，也就是能表示多大或多小的数。

mantissa / fraction 决定精度，也就是数值能表示得多细。

所以 BF16 的 exponent 多，范围大；FP16 的 mantissa 更多，局部精度相对更好。

---

### 4. FP16 和 BF16 有什么区别？

FP16 是：

```text
1 sign + 5 exponent + 10 fraction
```

BF16 是：

```text
1 sign + 8 exponent + 7 fraction
```

FP16 精度相对更高，但范围更小。

BF16 范围接近 FP32，因此训练更稳定，但尾数更少，精度更粗。

---

### 5. 为什么大模型训练常用 BF16？

因为 BF16 保留了 8 位 exponent，动态范围接近 FP32，不容易 overflow 或 underflow。

大模型训练中梯度、激活、loss scale 等数值范围变化很大，动态范围比尾数精度更关键。BF16 能在节省显存和保持训练稳定之间取得较好平衡。

---

### 6. FP8 的 E4M3 和 E5M2 有什么区别？

E4M3 有 4 位 exponent、3 位 mantissa。

E5M2 有 5 位 exponent、2 位 mantissa。

E4M3 精度稍好，但范围较小。

E5M2 范围更大，但精度更低。

在实际系统中，选择哪种 FP8 格式要看数据分布、硬件支持和量化策略。

---

### 7. INT8 能表示的范围是多少？

有符号 INT8 通常表示：

```text
-128 ~ 127
```

它一共有 8 bit，共 256 种状态。

负数通常使用补码表示。

---

### 8. 什么是补码？

补码是计算机表示有符号整数的一种方式。

求一个负数的补码：

1. 先写出对应正数的二进制；
2. 按位取反；
3. 加 1。

例如 INT8 中：

```text
+1 = 00000001
取反 = 11111110
加 1 = 11111111
所以 -1 = 11111111
```

补码的好处是可以把减法统一成加法。

---

### 9. INT8 和 FP8 有什么区别？

INT8 是整数格式，没有 exponent 和 mantissa，不能直接表达小数，需要借助 scale 把浮点数映射成整数。

FP8 是浮点格式，有 exponent 和 mantissa，可以直接表达不同数量级的小数，但精度和范围都受 8 bit 限制。

简单说：

```text
INT8: 量化整数，需要 scale
FP8: 低精度浮点，有指数和尾数
```

---

### 10. INT4 为什么能大幅降低显存？

因为 INT4 每个数只占 4 bit，也就是 0.5 byte。

相比 FP16 的 2 bytes：

```text
INT4 只占 FP16 的 1/4
```

所以权重量化到 INT4 可以显著减少模型权重显存。

但 INT4 表示范围和精度都很有限，所以量化误差更大，需要更复杂的量化算法。

---

### 11. 量化为什么需要 scale？

因为 INT8/INT4 是整数，而模型权重和激活通常是浮点数。

需要用 scale 建立浮点值和整数值之间的映射：

```text
int_value = round(float_value / scale)
float_value ≈ int_value x scale
```

scale 的选择会直接影响量化误差。

---

### 12. 数字格式如何影响推理性能？

主要影响三方面：

1. 显存占用：bit 越低，占用越小；
2. 显存带宽：每次从 HBM 读取的数据越少，memory-bound 场景可能更快；
3. 计算路径：不同格式是否能使用 Tensor Core 或专用 kernel。

因此低精度格式可能同时带来更低显存和更高吞吐，但前提是精度损失可控，并且 kernel 实现足够高效。

---

### 13. 为什么 KV Cache 也可以量化？

KV Cache 存的是历史 token 的 K/V 向量。

在长上下文和大 batch 推理中，KV Cache 会占用大量显存。

把 KV Cache 从 FP16 降到 FP8 或 INT8，可以降低显存占用和 HBM 读取量。

但 KV Cache 直接参与 Attention 计算，量化误差可能影响生成质量，所以需要合适的 scale 和 kernel 支持。

---

### 14. FP32、FP16、BF16、INT8、INT4 的关系怎么理解？

可以从两个维度理解：

1. 浮点 vs 整数；
2. 高精度 vs 低精度。

FP32/FP16/BF16/FP8 都是浮点数，能表达小数和动态范围。

INT8/INT4 是整数，主要用于量化，需要 scale 映射回近似浮点值。

bit 越低，显存越省，但表示能力越弱，越需要量化算法补偿。

## 九、最重要的记忆主线

这节课最重要的主线是：

```text
大模型输入、参数、激活、输出都是数字
  ↓
数字必须用某种格式存储
  ↓
浮点数用 sign/exponent/fraction 表示
  ↓
exponent 决定范围，fraction 决定精度
  ↓
FP32 精度高但占显存大
  ↓
FP16/BF16 节省显存并适配 Tensor Core
  ↓
FP8 进一步降低 bit，但更依赖硬件和缩放策略
  ↓
INT8/INT4 通过量化大幅降低显存
  ↓
量化需要 scale 把浮点值映射到整数值
  ↓
低精度格式影响显存、带宽、速度和模型精度
```

如果你准备 AI Infra / 推理框架面试，最应该能讲清楚三句话：

1. **FP 类型的核心是 sign、exponent、fraction；exponent 管范围，fraction 管精度。**
2. **BF16 比 FP16 更适合训练，是因为它保留了 FP32 级别的指数范围。**
3. **INT8/INT4 量化能省显存和带宽，但必须通过 scale 映射，且需要控制量化误差。**

---

## 十、一句话总结

大模型中的数字格式决定了参数和激活如何被存储、计算和搬运；从 FP32 到 FP16/BF16/FP8，再到 INT8/INT4，本质上是在显存占用、表示范围、数值精度、硬件速度和模型精度之间做权衡，而这正是量化和推理优化的基础。
