## 2. 为什么要转 AI 应用开发？

你可能会问，为什么现在要转 AI 应用开发？

我想先问你一个问题：如果问你这两年最火爆的技术赛道是什么，我相信 AI 大模型一定是很多人心中的答案。

从 ChatGPT 推出到今天，我们的生活正在被 AI 重塑。不管你对 AI 的接受程度高不高，每个人或多或少都在使用 AI。从人人都在用的自然语言问答，到程序员手里的 GitHub Copilot、Claude Code，再到之前很火的 Dify 社区，再到最近各种 AI Agent 产品，AI 已经不只是概念。

我认为 AI 不是泡沫，因为已经有很多商业化产品出现了。

作为程序员，我从 2023 年开始使用 ChatGPT、GitHub Copilot，到后来的 Claude Code。AI 编程能力的进步速度让我非常震惊，也让我感到害怕。短短几年时间，我明显感觉到程序员这个职业未来可能不需要那么多人了。

当然，我相信程序员不会完全被取代。但是未来中低端程序员，尤其是只会写重复业务代码的程序员，生存会越来越困难。

从我这次跳槽的经历来看，最直观的感受是：

第一，大厂在不断推出 AI 应用开发岗位。  
第二，AI 应用相关岗位的薪资明显高于传统业务开发。  
第三，AI 初创企业越来越多，而且很多初创公司给出的薪资甚至超过大厂。

这些不是空穴来风。

为什么？因为大模型底层能力的门槛比较高，未来真正能参与基础模型训练的玩家不会太多。AI 能否真正改变生活，很大程度上靠的是上层应用。

这就像早期互联网一样。信息技术和通信技术的发展，催生了大量 Web 应用和移动应用。程序员参与建设了繁荣的互联网时代。

如果说第三次工业革命的主角是互联网，那么第四次工业革命很大概率和 AI 相关。风口出现的时候，执行力就非常重要。

我们先不管未来 AI 到底会发展成什么样。对普通程序员来说，我们没有吃到移动互联网红利，现在 AI 应用开发这波机会，赌一把又能损失什么呢？

当然，我先声明一下，我不是卖课的培训机构。我是真的自己也在赌这一把。所以我推荐大家关注 AI 应用开发，不是为了卖课，而是因为我自己也在转这个方向。

## 3. 第一阶段：学习深度学习和大模型理论

接下来分享我的学习路线。

首先，我建议大家了解一些深度学习和大语言模型的理论知识。

你可以先了解基本的神经网络工作原理，比如：

- 什么是神经网络；
- 什么是反向传播；
- 什么是损失函数；
- 什么是优化器。

这些都是比较基础的东西。

然后，还要了解常见的网络结构，比如：

- 全连接网络；
- 卷积神经网络 CNN；
- 循环神经网络 RNN；
- Encoder-Decoder 结构；
- Transformer 结构。

这里面最重要的是 Transformer，因为它是当前大语言模型的技术基石。

学完这些之后，我建议再了解一些主流大语言模型的原理，比如 ChatGPT、DeepSeek、Qwen 等大模型的基本机制。你需要知道：

- 什么是混合专家模型 MoE；
- 什么是模型蒸馏；
- 大模型结构大概长什么样；
- 什么是预训练；
- 什么是后训练；
- 什么是 SFT 监督微调；
- 什么是强化学习。

虽然我们做的是 AI 应用开发，不一定每天都要训练大模型，但是这些理论还是有必要了解。如果完全不懂这些概念，会显得比较门外汉。

当然，如果你的时间非常短，准备不充分，这部分也可以先跳过，直接进入下一部分。

## 4. 第二阶段：学习 AI 应用开发框架

第二部分，我建议你学习 AI 应用开发框架。

目前比较主流的 AI 应用开发框架是 LangChain。简单做 AI 应用，用 LangChain 已经足够了。如果想深入学习，可以继续研究 LangChain 的底层设计。

不过 LangChain 主要支持 Python，不太适合 Java 和 Golang 开发者。

如果你是 Java 开发者，可以学习 Spring AI。  
如果你是 Golang 开发者，可以学习字节开源的 Eino。

因为我自己目前在字节工作，所以我主要学的是 LangChain 和 Eino。

这一块非常重要，因为这些框架可以帮助你快速开发一个 AI 应用。

以目前比较火的 LangChain 为例，至少要熟悉它的核心组件，比如：

- Model I/O；
- Chain；
- Memory；
- Agent；
- Tools；
- Retriever。

学完之后，你应该具备基于框架实现一个 AI 应用或者 RAG 应用的能力。

这里我推荐大家可以看看一些 LangChain 课程。不过需要注意，有些课程版本比较旧，LangChain 1.0 之后发生过比较大的更新。如果你想学 Spring AI 或 Eino，也可以自己找官方文档和项目资料。

## 5. 第三阶段：深入 RAG 和 Agent

学完开发框架以后，可以分两条路线深入学习：

第一条是 RAG。  
第二条是 Agent。

这两条路线相对独立。你学完框架之后，可能能写一个 RAG Demo 或 Agent Demo，但真正想做出优秀的 RAG 项目或者 Agent 项目，还需要继续学习很多东西。

---

## 6. RAG 学习路线

先说 RAG。

因为我工作中需要做 RAG 项目，所以在工作过程中做了大量调研。

我认为 RAG 的核心主要分成两块：

第一是文档索引。  
第二是文档召回。

文档索引阶段，你需要重点关注：

- 文档清洗；
- 文档切片策略；
- 文档 embedding；
- 文档元数据；
- 向量数据库；
- 索引结构。

文档召回阶段，你需要重点关注：

- Query Rewrite，查询改写；
- Hybrid Search，混合检索；
- 查询结果融合；
- Rerank，查询结果重排序。

当你了解了这些优化手段之后，就可以把它们应用到项目中，这会让你的 RAG 系统可用性大大提升。

当然，生产级 RAG 项目还需要关注 RAG 测评。因为我们不可能完全依靠人眼判断系统效果有没有提升。

此外，还有一些更复杂的 RAG 架构，比如引入知识图谱、GraphRAG 或其他结构化知识管理方式。这类实现难度会更大。

所以 RAG 这条路线其实要学的东西很多。学完 RAG 技术路线后，最好做一个 RAG 项目。

---

## 7. Agent 学习路线

再说 Agent。

我认为一个 Agent 通常由四个部分组成。

第一部分是大语言模型。它负责推理和生成，可以理解任务、生成策略。

第二部分是规划模块，也就是 Planning。它可以拆解任务，规划执行路径。

第三部分是记忆模块，也就是 Memory。短期记忆一般走上下文，长期记忆一般用知识库或者数据库。

第四部分是工具模块，也就是 Tools。它包含很多外部能力，比如：

- 搜索能力，如 Web Search；
- 执行能力，如查文件、写文件、跑代码；
- 外部交互能力，如调用外部 API。

除此之外，还需要了解 Agent 的主流工作框架。

最出名的是 ReAct 模式。它的原理其实很简单，就是边想边做。任务来了以后，先思考，再行动，然后观察结果，再继续思考、行动、观察。

这个模式的优点很明显：灵活，可以根据中间结果调整计划。

缺点也很明显：Token 消耗量很大，因为每一步都要调用大模型。它比较适合探索型任务、复杂任务。

还有一种模式是 Plan-and-Execute。它是先计划，后执行。任务来了以后，先规划出完整的任务列表，然后并行或顺序执行这些任务，最后把结果合并，完成任务。

这个模式的优点是效率高，可以并行执行多个任务。缺点是不够灵活，不能很好地根据中间结果调整规划。

除了这些，还有很多其他 Agent 工作模式。比如 Deep Research 这种专门解决复杂研究问题的 Agent 模式，之前也非常火。

现在很多 AI 应用产品已经是 Multi-Agent 协同系统，例如 Claude Code。如果想深入学习 Agent，我建议好好研究 Claude Code 的工作机制和架构设计。毕竟它是目前非常成功的商业化 Agent 产品，能力非常强。

总之，研究 Agent 一定要紧跟潮流，因为 AI 技术发展太快了。多学习新知识，多动手实践，一定不会错。

这期视频的真正主题是：

它解决的问题是：

- 怎么写 CUDA kernel；
- 怎么做算子优化；
- 怎么做推理引擎；
- 怎么优化 KV Cache；
- 怎么做 continuous batching；
- 怎么做模型量化部署；
- 怎么做 TensorRT-LLM；
- 怎么读 vLLM 源码；

所以，它更准确地属于：

> **AI Application Engineering / LLM Application Development**

而不是：

> **AI Infrastructure / LLM Inference Engine / AI Compiler / Model Serving Infrastructure**

# 第四部分：AI 应用开发、模型部署、AI Infra 的层级关系

很多人容易把这些词混在一起。你需要建立一个清晰的技术栈视角。

## 1. 大模型技术栈分层

可以把大模型相关岗位从上到下分成几层：

```text
第 1 层：AI 产品 / 业务应用层
第 2 层：LLM 应用开发层
第 3 层：模型服务 / 模型部署层
第 4 层：推理引擎层
第 5 层：算子 / 编译器 / 硬件加速层
第 6 层：训练框架 / 分布式训练层
```

对应内容如下：

| 层级 | 代表方向 | 代表技术 | 主要工作 |
|---|---|---|---|
| 产品应用层 | AI 助手、智能客服、代码助手、办公自动化 | Prompt、工作流、业务系统 | 把 AI 做成用户可用产品 |
| LLM 应用开发层 | RAG、Agent、工具调用、多轮记忆 | LangChain、LangGraph、LlamaIndex、Spring AI、Eino | 连接模型、知识库、工具和业务系统 |
| 模型服务层 | 模型部署、推理服务、MLOps | Triton、Ray Serve、KServe、FastAPI、Docker、K8s | 把模型变成高可用服务 |
| 推理引擎层 | 大模型推理优化 | vLLM、TensorRT-LLM、TGI、llama.cpp、MLC LLM | 优化延迟、吞吐、显存、并发 |
| 算子/编译器层 | 算子开发、图优化、AI 编译器 | CUDA、Triton Language、TVM、MLIR、CUTLASS | 写 kernel、做算子融合、硬件适配 |
| 训练系统层 | 分布式训练、训练框架 | PyTorch、Megatron-LM、DeepSpeed、FSDP、NCCL | 训练大模型，优化通信和显存 |

本视频主要讲第 1、2 层，最多涉及一点第 3 层的项目部署意识。  
你之前一直关注的 **AI Infra 推理侧**，主要是第 3、4、5 层。
