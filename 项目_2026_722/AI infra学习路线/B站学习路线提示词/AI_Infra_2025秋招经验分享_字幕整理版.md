## 第二部分：AI Infra 岗位方向与面试问题

我做了一个思维导图。这些岗位的知识其实有很多是不同用的，后面我会提到。

好的，谢谢。还有同学有问题吗？

OK，我们进入第二部分。最近有一些同学还在群里发了一些问题，这是我列出来的七条，前三条都是问算子的一些问题。我做了一个思维导图，大概整理了面试会遇到的一些岗位和对应问题。

首先第一个问题：搞推理方向，有哪些方向和岗位可以投？

这个其实有很多。像 AI Infra 的话，我大概把它分成了几个大的方向和岗位。

第一个就是高性能计算，或者异构计算工程师，这是比较经典的岗位。这个岗位在公司里面主要做的任务，就是维护一个算子库，或者两个算子库。核心任务就是写算子。

像互联网公司，一般会有两套技术栈。英伟达的技术栈是最多的，因为会买很多英伟达的卡，所以会维护一套 CUDA 算子库。同时也可能会买华为的卡，比如百度、字节、腾讯都有买很多华为的卡，美团也会维护一套华为的算子库。

这个岗位最多的工作就是写算子和优化算子。我觉得这个岗位的面试也是最难的那一部分。

其次就是大家比较了解的 AI 推理引擎、大模型推理引擎工程师。这个岗位目前招得也比较多。它相比来说，工作就是去写推理框架、维护推理引擎。尤其是在自研芯片公司，这种岗位招得也比较多，因为他们会根据自己的 AI 芯片去做上层框架适配，比如昆仑芯、M2【疑似】这些芯片，会适配自己的 vLLM 和 SGLang。

然后就是训练框架研发工程师，这个相对来说比较少。只有那些要训练自己大模型的部门，才会二次开发 Megatron、DeepSpeed，还有 PyTorch、TensorFlow 这些框架。

再就是 AI 编译器。AI 编译器招得最多的肯定是自研芯片公司，还有互联网公司的自研芯片部门，比如腾讯的相关实验室、阿里的平头哥和大模型院、百度昆仑芯这些，都会招 AI 编译器相关岗位。

## 一、高性能计算 / 异构计算 / 算子开发岗位

我们先来看第一个，高性能计算或者异构计算工程师。这个岗位面试时可能遇到的高频问题，首先就是必须会 CUDA。面试的时候，手撕 CUDA 是一定会存在的。

也有同学问，CUDA 会考到什么程度。一般来说，面算子组的岗位，举例来说，Softmax、RMSNorm、LayerNorm、MatMul 这些比较经典的算子一定会问到。手撕的话，也经常从这几个里面出，尤其是前两个。

然后会问一些比较经典的问题，比如如何解决 bank conflict。我们在写算子的时候，面试官会问你怎么分析一个算子，怎么去优化。肯定要进行一个 Roofline 分析，分析它是 compute bound 还是 memory bound。也会问到这个算子的 tiling 和 pipeline 策略，这些都是比较经典的。

然后就是关于 FlashAttention。FlashAttention 现在有三个版本，FA1、FA2、FA3，八股也是经常问到。很多组可能会让你说一下 FA1、FA2。FA3 不太可能让你手撕，因为它太难了。

在回答 FlashAttention 的问题时，我的建议是从前往后铺垫。因为这个技术出来之前，是有一段演进过程的。比如一开始只是有一个 online softmax 的内部版本，解决不存完整 softmax 矩阵的问题。后面是 safe softmax，只是减了 max 的值，解决溢出问题。然后又出来一个 online softmax，它有 kernel 的影子。后面出来了 FlashAttention 1，再后面是 FlashAttention 2，重新设计了算法，用时间换空间。FA3 就是 Hopper 上的应用，用上 TMA、WGMMA、FP8 这些技术。WGMMA 在 FA3 里也要提到。

然后从 CUDA 到 PTX 到 SASS 这条链路，至少也得了解。

关于上面这些内容，有一个比较好的 GitHub 仓库，是 DevTrue【疑似】这位大神维护的。我感觉是神中神，很多同学应该都知道他是谁。他维护了一个比较经典的仓库。这里边也有同学问新手学习路线，我感觉学 CUDA 的话，有些算子可以从这里开始写。因为他几乎把所有的算子都实现了一遍，而且实现得比较好。FP16、FP8、BF16 基本都实现了，还有 CUTLASS 的用法、单精半精矩阵乘【疑似】、卷积成像等，以及他自己写的 FlashAttention 优化版本。

后面大模型相关的，他也有很多文档，还有总结的一些 paper。还有 CUTLASS 相关内容。像 Reader【疑似】也是大神，他现在好像也在蔚来的某个高性能计算组，叫路晓泽【疑似】。他基本上把 CUTLASS、CUDA 软件栈、新特性都了解得非常清楚，写的文章也比较有深度，推荐大家看一下。

有同学问 Hopper 会问得很多吗？这个要看岗位。如果面的是算子组，CUTLASS 那些比较难的问题肯定会问到。比如每一代显卡、CUDA Swizzle、TMA、MMA、Hopper 最新的 FA3、TMA、WGMMA 这些用法，基本都会问到。CUTLASS、cuDNN 这些现成库的用法，对于面算子组也是会问到的。性能分析工具，比如 Nsight Compute 这些用法，也会问到。

这个导图其实做得不是很全面，我后面可以把原文件发给大家，大家可以自己再拓展。

对于 NVIDIA 的架构发展史，也建议大家去看一下。因为我之前面某些公司时，遇到过 NVIDIA 出来的面试官。我印象很清楚，他问我为什么 Tensor Core 会发展到现在这样。当时就有点尴尬，说实话我确实不知道它发展的顺序，后面才去补的。

从 Volta 到 Turing，到 Ampere，到 Hopper，到 Blackwell，Tensor Core 的发展史为什么会变成这样？无非两方面：第一是算力提升，第二是访存加速。之前一代一代从 FP32、FP16，到 FP8、INT8、INT4 这些精度下降，带来算力提升。后面是访存加速，比如 Hopper 上加了 TMA，张量内存加速，所以访存变得更快了。这些大概都需要了解。

还有一个经典问题也肯定会问：NVIDIA 的内存层级。我们写一个 CUDA 程序，它执行的时候，内存访问层级是什么样的？从 HBM，到 L2 cache，到 L1 cache / shared memory，再到寄存器，大概这个流程也会问到。

NVIDIA 这套技术栈，前两年可能问得不是那么多，但在未来这么卷的情况下，这些肯定会包含 80% 以上的问题，起码要知道。

后面就是华为系列。在华为卡上写算子的话，NPU 技术栈问得可能不是那么多，但要了解。比如 Ascend C 写算子、910 系列、性能分析工具，还有 MindSpore、CANN 这些框架，要了解一下。

寒武纪、燧原、壁仞、沐曦、互联网自研芯片这些公司，在招人的时候一般不指望你完全懂他们自己的写算子工具或者框架。你只要把通用的学会了，面试问得还是 NVIDIA 比较多，还有华为这些通用的。你会了这些，基本上这些公司的岗位问题覆盖得差不多了。

这大概就是高性能计算和异构计算岗位的高频面试问题。

还有前三个问题里，有同学问算子岗位对 CUTLASS 要求什么。刚才也说了，肯定是有要求的，而且算子岗位面试难度不低。

还有算子开发和上层推理框架怎么选择？这两个是选择问题。我觉得推理框架既能搞上层的推理调度，又能搞下面的算子。但推理引擎里的算子，应该没有算子组写得那么深，不过面试也没有算子组那么难。我是这样理解的。

## 二、关于显卡、LeetCode 和模型部署的问答

我先回答“看海的人”这位同学的问题：如果只有 3060，我觉得会有影响。30 系列是 Ampere 架构，其实也还好，写算子来说够了。但如果你想把 Tensor Core 用得比较好，肯定要去租 A100。AutoDL 上可以租 A100 系列。要做分布式推理的话，一张卡肯定是不够的。

有同学问：面算子岗位还用准备一般的 LeetCode 算法题吗？还是说手撕直接手撕算子？

LeetCode 也得准备。但是我觉得算子组一般 90% 都是直接考算子。从去年情况来看，LeetCode 也得准备，因为说不准面试官会问。

还有同学问：现在目前有华为 NPU 技术栈，还需要补一下 NVIDIA 技术栈吗？

我觉得要看你主要想面什么公司、什么部门。如果你只会华为 NPU 生态，可能只能去国产芯片厂。国产芯片公司虽然会问华为 NPU，但 NVIDIA 的东西你也得懂，不用学得那么深，比如 CUTLASS 不用学那么深，但 NPU 这个方向你必须学得深一点。

国产芯片的话，对手撕算子要求可能还不是那么高。想走模型部署可能会简单一点，因为它主要是用现成框架做量化部署、精度对接这些任务，和算法部门对接，相对简单一些。但是因为它简单，所以面的人多，不一定容易拿到 offer。

我的建议是，不要把模型部署当作主攻方向。还是以推理引擎作为主攻方向，然后模型部署也投。因为你学得越多，模型部署岗拿到的概率也会更大。如果把模型部署作为主攻方向，offer 可能不是那么好拿。

我举个例子。我本科的时候在专业里面最后是专业第二。我以专业第一为目标去考试，每次成绩可能都只比第一低一点。但如果我的目标只是前五，那我可能每次考得比前五还低。这个例子就是说明，你准备的目标不一样，准备的知识范围也不一样。

很多量化部署岗位也算 AI Infra 方向，但难度相对低一些，都是用现成框架去做量化部署。

## 三、AI 推理引擎和大模型推理引擎

我们继续聊后面的问题：推理框架，比如 vLLM、SGLang 和 llama.cpp 这些对应岗位怎么样？

第二个岗位就是 AI 推理引擎和大模型推理引擎工程师。其实大模型推理引擎和 AI 推理引擎是有一定区别的。

在大模型没有这么火之前，就已经有 AI 推理引擎岗位。比如腾讯的 TNN、阿里的 MNN、英伟达 TensorRT、华为 MindSpore Lite，还有 NCNN 这些，都算 AI 推理引擎。

大模型推理引擎大家可能更熟，比如 vLLM、TensorRT-LLM、SGLang、llama.cpp、KTransformers【疑似】等。

为什么要把它们区别开来？我觉得最大的区别是有没有 IR 中间表示。有 IR、有图层优化的，基本是传统推理引擎。比如 NVIDIA 已经有了 TensorRT，为什么还要再开发 TensorRT-LLM？因为大模型的算子种类比较少，核心就是十几种。相比之下，之前的视觉模型动不动就有各种算子、各种中间层，所以用图层优化、IR 中间表示比较好。

大模型因为算子种类比较少，所以只需要把这些算子熟练地串起来。大模型推理框架会对解码、KV Cache 这些优化得更细致。

这大概就是推理引擎方面的知识链。面试的时候也会根据不同方向问不同问题。

有同学问：面试需要手撕矩阵乘吗？

有的需要。像阿里云有些面试官就喜欢问手撕矩阵乘，八股加优化方式，甚至手写一下都是有可能的，不能完全不会。至少要知道是怎么回事。

除了大模型推理引擎，常规推理引擎基本会问到 IR、模型转换、计算图、切图、算子融合、算子调度、Pass、pipeline、整图优化、CUDA Graph、单帧下发优化、模型并行推理调度、动态图转静态图等问题。

大模型推理引擎没有这么多计算图相关问题。

去年 vLLM 比较火，问得比较多的是 vLLM 里的内容。比较经典的就是 PagedAttention，一般不止问 PagedAttention，还会问 vLLM 为什么有高吞吐、显存管理特点、continuous batching、Orca 这类 batching 问题。这些都是常规八股，不是特别难。

TensorRT-LLM 现在没有那么火了。它当时对一些量化实现得比较好，所以一般会问量化，也会问量化算子是怎么实现的，还会问为什么有了 TensorRT 还要写 TensorRT-LLM。

SGLang 是去年年底到现在比较火的大模型推理引擎。它问得比较多的是自己的 DSL、流式返回、调度、KV Cache、request 管理等。

有同学问：大模型推理引擎推荐看哪一个？

我觉得现在面试的话，vLLM 和 SGLang 这两个都要看。vLLM 因为 PagedAttention 的存在特别经典，要看它怎么做 continuous batching 和减少内存碎片化。SGLang 是今年初到现在特别火，也得看它的八股和图优化【疑似：此处可能是“调度优化”】。

没有相关实习有没有机会？也是有机会的。

本科生找工作中，大模型推理引擎肯定是八股问得多。像 vLLM 和 SGLang，刚才提到的八股会问得比较多。当然也会问 CUTLASS，也大概率会让你手撕算子。大模型推理引擎岗位里，LeetCode 的概率可能比手撕算子大一点。

常规推理引擎的话，TensorRT 要会用，TNN、MNN 这些开源项目也可以去看。

工作场景上，如果是自研芯片公司对自己的芯片做适配，像 vLLM 和 SGLang 必须从前到后都理解，因为它要二次开发。工作的日常就是给自己家的芯片做二次开发适配。如果连 vLLM 和 SGLang 是什么都不知道，那肯定不太行。所以面试也会问得很深，尤其是自研芯片部门。

端侧推理和大模型推理的场景不一样。端侧模型算力少，一般只有双 Orin 或者四 Orin【疑似】，芯片少、算力低，跑不了大模型推理。大模型场景一般是八卡、双八卡这种场景。端侧就是算力很低的场景，两者完全不一样。

我的经验是，我之前在蔚来实习完之后，去面大模型的一些公司，端侧推理经验其实完全用不上。

上手学习没有什么特别好的方法，就是先跑通，然后 debug 打断点，看每个关键节点上模型是怎么跑的。底层算子怎么跑起来的，quip a llama【疑似】讲得特别好，算子的写法以及怎么串起来跑的过程，讲得比较好。

## 四、算子开发准备、推理是否需要分布式

刚才有同学想听算子开发的准备选择和往后规划。算子开发的话，这些担心我觉得都有必要，但不用考虑得那么深。

如果是新入学生入门，想写算子的话，可以从 CUDA 开始，从 DevTrue【疑似】那些大神的仓库开始学。还有学 quip a llama【疑似】。

刚才有同学问：推理需要掌握分布式吗？

去年有一些相关技术，比如大模型推理的分布式技术，不仅能用在训练里面，也能在推理场景中用来做适配。比如 TP，张量并行、专家并行、数据并行、6D 并行，都需要了解。

## 五、常见高性能计算 / AI Infra 公司和部门难度

下面这一部分大家可以好好听一下。我列一份常见高性能计算公司、有 AI Infra 岗位的公司和部门。

我可以列一个难度排行榜。从前年到去年这两年，我觉得面试难度可以分为五级，从 T0 到 T4，就像游戏英雄等级一样。

T0 是 NVIDIA、AMD、高通。这三家去年是开了实习和校招的。我觉得这三家面试应该是最难的，不管是技术考察难度，还是 HC 比较少，大家应该比较认同。首先它难，然后 HC 少。

T1 包括阿里云、通义实验室、字节【疑似】、AMD【此处原字幕混乱，可能指某些头部 AI Infra 部门】。这些应该是互联网里面比较强的一梯队。百度 Paddle 也算比较强。我觉得这几个面试比较难。

阿里云和通义实验室难在哪里？技术考察难，竞争卷，投的人多。最重要的是比较卡学历，基本现在卡到 C9 / 985，211 / 985 也不好进，HC 还少，所以这些因素导致难。

字节和 AMD【疑似】也是这样，它肯定比较看本科和实力。实际也有特别优秀的同学能进面，但双非进面难度很大。除非你是 vLLM 核心作者这种情况，可能有机会。

这些公司的难点，一方面是技术考察难，一方面是竞争卷，HC 少。字节去年到今年其实 HC 不是那么少，它在广泛招人，但难在它想招很强的同学。比如今年有一些顶尖实习，日薪一两千，基本要很强的博士和硕士。

第二级别，我这里列了一些。比如腾讯的自研芯片，它比较卡学历。我了解的部门基本都是清北比较多。为什么？因为这些清北同学表现得非常好，零经验都能一周写出融合算子，做芯片上的分布式推理适配。之前没学过也能上手，这也是我觉得清北一些同学比较强的原因。

然后是腾讯混元。相比上面来说，简单一点，但也比较难。

百度 Paddle、昆仑芯，投的人很多，每年招得也不少，但竞争也卷。

美团机器学习引擎、大模型推理引擎，也是竞争卷，HC 少。

阿里大模型院去年招了很多人，卡学历也不便宜。清华的一些学院，可能直接去那儿宣讲。算子组去年上海内部也招很多，但 HC 少。

接着是星辰、小红书这些。面试上整体来说比上面难度低一些。为什么把这些公司排到后面？因为每年技术强、学历好、有很多对口实习的同学，肯定会被前面的公司和部门收走，后面这些公司再收后面的同学。

所以有些同学可能觉得蔚来、理想、小红书、小米、自动驾驶公司这些岗位也不是那么简单，但相比前面来说，会稍微低一些。

T4 / T5 就是各种不知名芯片公司。

华为其实也很强。如果华为能拿到 16 级、15A 或 16 级，那就是 T1 / T2；如果拿到 13A，那就另说。

平头哥技术很强，但去年可能没招满。可能是大家觉得它难，或者知名度低一点。我觉得它挺强的，但是去年招得比较久。

大概是我个人的理解，不一定对，只是个人理解。

## 六、博士、论文和岗位匹配

有同学问：寒武纪难度如何？

寒武纪技术上没得说，面试难度也是有的。但还是那句话，很强的同学会被更强的 AI Infra 部门和公司收走。寒武纪技术上肯定没得说，难度也挺高。

有同学问：如果是做视觉出去的，比如硕士毕业工作四年再找，和博士毕业直接去企业界，会不会差不多？

我觉得个人因素比较大。很强的博士最近机会很多，比如很多公司都开了人才计划，不光是字节、百度这种算法部门，很多 AI Infra 部门也开了日薪一两千的实习岗位，面向博士和很强的硕士。如果博士能去这种部门实习，钱也没少赚，知识也学到，还能拿 return offer。

如果是纯读博士，不去外面实习，毕业之后再出来业界找工作，可能就要看个人实力，会有一定难度。

有同学问：他本课题【疑似：可能是“他本科学校/课题”】好不好用？

如果你是计算所、中科院某些所，那肯定相当好用。百度智能云、百度智能源【疑似】技术上没得说，大模型高性能优化和自动驾驶高性能引擎都可以做。我可能建议做现在比较火的大模型。自动驾驶 AI 引擎是针对端车的，端车芯片不多，也用不到分布式大模型，不如去做大模型，因为它现在也比较火，校招岗位多。

无问芯穹很强，我了解它很强；清程智能了解不多。

美团北斗的机器学习引擎和大模型引擎都会招。博士如果发了 PPOPP、HPC、OSDI 这种 paper，肯定很有用，而且还能拿人才计划工资。

有同学问：PPOPP 对 AI 应用有帮助吗？

如果只是面试，应用方向了解就行。如果希望自己的工作年限更长，拓展知识面，之后跳槽选择更多，肯定也要学一下。现在很多应用都要调用 AI 推理引擎的 API。

微调就更像算法问题了，这是算法和 Infra 的选择。我觉得目前不好说，要看个人兴趣。如果你很喜欢 Infra，可以转；大模型微调经历对 Infra 也有一定帮助，校招时有背书能力，不能说一点用都没有。

广告模型的 AI Infra，算自然意义上的算子比较多，和常规模型确实有一定区别。但找工作时，如果有广告模型经验，对广告相关 Infra 岗位肯定完全匹配。大模型 Infra 的话，还要多学一些。

集合通信是否需要了解？要看你进的组干什么。如果组里写算子，尤其训练相关算子，那肯定要了解集合通信。因为训练要写 all-gather、gather、all-reduce 等集合通信算子并维护。最近一些框架在华为 NPU 上的集合通信也需要做适配。

有同学问：博士如果想走 AI Infra，是不是发 OSDI、SIGCOMM、PPoPP 这种论文会更好？

我大概明白了。比如 OSDI 是 systems 领域顶会，HPC、PPoPP 这些整体来说偏 Infra。最近 AI Infra 相关内容在这些顶会里也多起来了。去年有一个本科同学在北航，去了阿里云，发了一篇 OSDI。秋招的时候，顶级公司和部门给了很高的价。博士找工作，公司部门可能更希望你进去带组、带人，拓展一个方向。

所以 OSDI 这类论文还是更倾向于 AI Infra。现在 AI Infra 也不只是开发，有些公司会叫高性能算法、大模型算法。算法和开发的边界没有那么大。论文对找工作有用，但要看方向是否对口，博士找工作很看对口程度。

去年发一篇 OSDI 的同学，总包可能在 100 到 150 万左右。没有顶会论文的，也可能拿到 100 万总包，这是去年的情况。

我个人对岗位面试难度的排名是：

## 八、AI 编译器 / 工具链 / 加速工具链

第二部分最后一点，说一下 AI 编译器和工具链、加速工具链岗位需要了解到什么程度。

首先肯定会问：你知道哪些 AI 编译器？比较经典的有 TVM、TPU-MLIR、IREE、Triton、LLVM 等。

TVM 比较老，开发比较重，它是一个端到端的 AI 编译器。

TPU-MLIR 是算能开发的端到端 AI 编译器。如果想学 AI 编译器，我建议大家可以学一下。它提供了比较完整的视频和文档教程，比如 AI 编译器是什么、从前端到后端的转换优化、图优化等等。它也会有最新的 backend 支持新模型。代码没有 TVM 那么大，相对比较简洁。

IREE 也是一个端到端 AI 编译器，现在开发也稍微重了一点，也支持 PyTorch，建议大家可以了解。

Triton 问得比较多，因为很多自研芯片公司会用 Triton 做图编译或者 kernel 开发【疑似】。可能会问你知不知道它的 Dialect，有没有用 Linalg。Linalg 是最近比较有用的线性代数 dialect，也比较难。

Triton 大家应该了解比较多，它是一个便捷的并行编程语言。

MLIR 全称是 Multi-Level Intermediate Representation，多级中间表示，不是基于 LLVM IR 单层中间表示，而是多级中间表示，这也是可能会问的。

最后也会问你知不知道 LLVM。

AI 编译器问起来，广度大概就是这些。深度上，首先会问 TVM 和 MLIR 的区别。TVM 是一个已经写好的单独端到端编译器，输入一个模型，输出二进制代码，可以在 GPU 或 CPU 上跑。MLIR 是一个写编译器的工具，它支持端到端编译流程，包括模型转换、前端图优化、计算图优化、fusion、切图、后端 lowering、codegen、cost model 等。

面试不像算子开发岗位那样让你手撕算子。它基本上不会让你写算子，但会问一些图的数据结构和 LeetCode。极大概率会问或者考图的拓扑排序。因为计算图是 IR 计算图，它执行是按照拓扑序来的。我在某些面试里都遇到过手撕图的拓扑排序。

所以如果想面这种岗位，图的数据结构和 LeetCode 要刷一下，尤其是拓扑排序。

先学前端还是后端？我的建议是从 AI 编译器前端学到后端。前端从 ONNX 最简单，从 ONNX 转换成 IR/Dialect，再走 Pass、Pass pipeline，然后往下到 codegen。整套链路得从前往后学，才学得明白。

## 十、图优化示例

有同学问：端侧学 TensorRT，对大模型 SGLang 和 vLLM 的图优化有帮助吗？

大模型推理引擎基本没有计算图优化，图优化主要是端侧的东西。这里我分享一下什么叫图优化，或者举几个例子。

比如针对 TVM 加 TensorRT 的计算图优化。一个模型在量化时，最后一层 sigmoid 和 softmax 量化掉点非常严重，这时用校准集也不好使。有用的解决方法就是在计算图上用 Pass 把它切出去。最后这一层切出去用 CPU 跑，这样就变成两个子图：前面的子图跑在 GPU/NPU 上，后面的子图跑在 CPU 上。CPU 上跑这个算子，掉点就没有那么大。最后前后串起来，这就是计算图优化里的切图 Pass。

还有一种情况，做 INT8 量化时，中间某些层掉点。我不想把后面的所有子图都跑在 CPU 上，因为这样速度慢。怎么办？可以在中间阶段把某些层设置成 FP16 或 BF16，这样做混合精度推理，这也是图优化的一种。

还有一种情况，有些推理框架不支持某些算子，或者芯片不支持某些算子，导致编译不了。可以用图优化方式写 Pass，把这个算子转成其他等价算子的组合，这样就解决了。

还有 fusion 算子，模型转换时的各种问题，比如某些算子形状从向量变成标量，导致 Pass 报错，也可以通过写 Pass 解决。

这就是大概的图优化内容。

训练框架我接触不是很多，主要是根据周围同学面试情况来讲。确实面这个岗位的同学不是很多，我自己也没去面过训练框架岗位。周围有推理背景的同学也能进入这种岗位，所以训练框架虽然知识点多，但因为投的人不是那么多，面起来不一定最难。

## 十二、Linux 驱动背景和 AI Infra 的对比

有同学问：Linux 内核和 AI Infra 相比，难度和前景怎么样？

同学说：我之前是搞 Linux 的，做 Linux 驱动和一些相关开发。但最近对 AI Infra 感兴趣，不知道整体难度和发展前景怎么对比。AI Infra 这两年很火，但 Linux 感觉更持久一点，不知道怎么看。

回答是：你说 Linux，是在给 Linux 写驱动吗？

同学：对，Linux 写驱动，做一些底层开发。

其实有比较相近的岗位。很多 AI 芯片公司对 Linux 内核和驱动也有需求。另外芯片公司也会有 Runtime 的需求。Runtime 相当于介于推理框架和驱动之间的一层。如果你想转方向，这两块可以重点看：AI 芯片公司的驱动，还有 Runtime。

关于前景，我感觉 Linux 现在比较稳，但薪资可能相对 AI 芯片低一点。AI 芯片这一块稳定性将来怎么样不好说。你可以不用完全押宝 AI 芯片，可以结合自身过往经验，找跟 AI 有关的 Runtime、驱动方向去接触。后续如果国内 AI 芯片突然不行，你还可以转回原来的驱动开发，因为 AI 芯片上的驱动本质上也是驱动。

不用完全押宝推理框架开发。你可以在推理框架上往底层走一部分，就是 Runtime。Runtime 其实是对一个芯片上的整体资源做把控，包括 kernel 执行、资源调度、计算资源调度等。现在这类岗位需求还可以，可以去看一下。

如果说做 Linux 和 AI Infra 的薪资对比，AI Infra 可能比头部 Linux 岗位高一些。但很多同学也拿不到头部 AI Infra 的薪资，所以整体差距也未必特别大。

## 十三、端侧推理和大模型推理

有同学问：做端侧推理要想清楚吗？端侧推理的业务场景有哪些？

端侧推理主要场景：机器人、智能家居、自动驾驶、无人机、大疆这些端侧设备。只有这些带 AI 模型的设备才有端侧推理需求。

所以端侧推理可以从自动驾驶、机器人岗位开始找，岗位难度相对低一点。

如果想往大模型上靠，还是学 vLLM 或 SGLang。端侧推理前几年，在 2022 年底大模型出来之前，自动驾驶比较火，资本也往那里倾斜。但这两年大模型火起来后，资本更多往大模型倾斜，端侧推理热度稍微降了一点，但目前也还可以。

vLLM 或 SGLang 的学习路线，我个人是从知乎、博客上找一些从零理解 vLLM 的资料。对于自学的人，可以把项目拉下来，先跑通一个大模型，然后 debug 打断点学习。学的时候要知道每个引擎的特色，比如 vLLM 的 PagedAttention、continuous batching、减少显存碎片这些特点。SGLang 也一样，学习它的调度、请求管理、KV Cache 管理等重点。面试主要问这些。

大家可以去搜它们的特点，然后去官方文档、博客看具体是怎么实现的。面试也不会所有内容都问。

## 十七、算子开发、推理框架、AI 编译器长期性

有同学问：算子开发、推理框架、AI 编译器，哪个更长远？

我感觉 AI 编译器可能更长远一点。

算子开发不太成体系，而且现在有 Triton，还有一些新工具。算子开发的知识比较零碎，日常可能就是维护一个算子库。

AI 编译器是一个完整框架。你想独立开发一个 AI 编译器，它是一整个框架；推理引擎也是一个组在维护一个框架，有自己的一套东西。这个组一般不会轻易被干掉。

算子的话，如果这个组不是特别重要，推理引擎组也可能替代一部分算子开发。比如推理引擎开发也能写算子，或者用现成算子库。如果是 NVIDIA 平台，很多固定算子他们也能写，不一定单独维护一个算子组。

长远来看，我感觉 AI 编译器更长久一点。

另一个补充是：算子开发看个人。有些人会觉得比较枯燥。每个功能开发都比较分散，比如现在开发一个 MatMul 算子，过段时间又开发一个 Attention 算子。你做的东西像是在打磨每个零件，把每颗螺丝拧好，但是没有形成一个整体产品。

推理框架也好，AI 编译器也好，是成体系的项目开发。算子库无论是项目开发还是个人参与感，都比较散。

学习上也是这样。大家很容易学一个 Softmax、MatMul、矩阵乘算子，感觉两三天就学得差不多了。但是两三天想学一个推理引擎或者 AI 编译器这么大的项目，肯定不够。所以单纯学算子，我建议不要只停留在这里。相比推理框架和 AI 编译器，算子的发展场景会稍微窄一点。

有同学问：推理框架跟芯片近吗？比起 AI 编译器呢？

推理框架和 AI 编译器不是谁替代谁的关系。AI 编译器组开发出来的成品会交给算子团队，让他们开发算子；算子团队用 AI 编译器开发出算子之后，要集成到推理引擎或推理框架里面。它们没有谁替代谁的关系。

如果说谁离底层更近，AI 编译器会离指令集和硬件体系结构更近一些。但岗位上不存在谁替代谁。

## 十八、为什么传统 Java / 后端 / App 开发被说“到头了”

有同学问：为什么传统 Java 后端那一套快到头了？

这是相比来说的。2010 年到 2020 年，手机快速发展，4G 出现，带来了大量 App 开发、网站开发需求。那十年是 Java、安卓、iOS、前后端的黄金十年。

这几年相比前面那段时间，需求下降很多。因为 App 开发差不多了，网站也开发差不多了，没有那么多新的需求了。现在更多是存量市场。

最多最近两年 AI 应用、AI Agent 相关应用多起来，可能带动一些前端、后端开发，比如 AI Agent 的前端展示、Java 后端服务，但最多也只是回光返照一下，量不会那么大。

其实 Java 后端还好，App 开发真的是存量岗位。我本科 2015 到 2019 年，那段时间安卓开发特别火，每天都有新应用上架，很多优秀学长都去做安卓或者 iOS。但等我研究生毕业时，iOS 和安卓开发基本上已经没有那么多新人需求了。

前端我觉得还是有的，比如微信小程序、各种展示层需求，这个需求一定存在。

## 十九、Kubernetes、云原生和训练岗位

有同学问 Kubernetes。Kubernetes 算真正意义上的云原生技术。之前云原生很火，最近 AIGC 群也在办 Kubernetes 技术分享。

如果是训练框架或者训练相关岗位，肯定要懂一些 Kubernetes，因为它和集群维护、调度相关。

## 二十、嵌入式 / C++ / 后端背景如何转

有同学说：我本科是做嵌入式的，现在在 985 读研，方向是硬件，前面一直在学 C++，也想过做后端。但是发现岗位越来越少，所以想咨询建议。我之前想做嵌入式，所以对 Linux 驱动有好感。但 Linux 驱动好像都是 C 写的，和 C++ 关系不大。我当时学 C++ 是想做后端，但是岗位越来越少。

回答：如果单纯做后端，现在 Go、Java 在性能上完全够用，没有必要用 C++ 做后台。因为 Go、Java 在脚手架、语言特性上更适合外部后台开发。C++ 后台可能金融量化有需求，比如交易程序，但那个方向对学历要求更高。

学历并不是第一因素，主要还是看实习和项目经历。

同学又问：我老师放养，我可以去实习。是先找个小公司实习，还是花几个月提升能力，然后直接找更好的公司实习？

回答：我觉得你可以先学一下，入个门，然后去找实习。在实习里，因为你有针对性方向，就往这个方向补齐。你花很多时间在学校里，一个是效率可能低，另一个是可能看不到方向，每天花很多时间在各个方向上，最后学得也不是特别精。

可以先学一段时间，比如三个月左右，然后投下半年的日常实习。找到实习后，在实习里补齐相关技术栈。如果中小公司不合适，再换下一段更大的实习。

AI Infra 方向能造轮子的小公司其实也不多，因为这个方向造轮子比较难。

有同学问：AI Infra 对学历卡得厉害吗？

这个看公司和部门。一般来说，不是所有公司都卡。像阿里云、P 系、头部部门肯定卡本科。字节有些不太卡本科，但也要有非常多实习经历。985 硕士想找 Infra 工作还是能找的，但如果想找得好，还是得有实习。

## 二十一、实习中怎么利用 GPU 资源做推理优化

有同学说：我现在实习的地方做量化框架，也做 vLLM 和 SGLang。但我 LeetCode 水平比较差，今年要秋招了，感觉有点来不及。我在一个小公司实习，公司有很多卡，可能有七八十张 A100、H20。主要做模型部署和推理，比如给量化后的模型用，或者给平台用 DeepSeek。导师让我做推理加速，从 vLLM 框架出发，但我有点迷茫。有没有建议，怎么利用这段时间和这些卡，做一些能提升水平的事情？

回答：这个问题不只是实习会遇到，以后工作也会遇到。你要先问清楚，导师到底想让你优化哪一块，或者他是否已经收集到业务部门的需求：在哪个环节出现性能瓶颈。你可以和业务部门交流，结合你们自身场景和业务做优化。

泛泛地说“优化推理”是比较难的，因为开源社区可能已经做得很厉害了。你要结合具体场景，比如在某个业务场景里确实遇到某个问题，然后搜集具体信息，往这个方向钻，看看有没有好的办法。

同学说：现在很多卡都闲着，能不能利用起来提升自己？

回答：如果搞推理，卡多其实也没那么有用。卡多更多是训练有用。

关于训练加速前景：训练框架加速、分布式并行那套前景肯定好。因为现在大模型训练不做分布式不行。但训练可能会慢慢收敛到少数几个头部公司，因为成本很高。

有同学问 ONNX 转 TensorRT 报错。我感觉要么是 layout 转换有问题，要么是某些算子没有支持，需要自定义算子。你尝试自定义算子可能也有问题。

集合通信肯定要多上经验。因为你做分布式并行那套模块，需要验证你写的集合通信在分布式训练里能不能行，这肯定需要经验。

我比较赞同之前说的，如果有驱动或者 Linux 内核经验，可以尝试搞 Runtime。可以去看 AMD 的 Runtime 那一套。现在很多国产芯片公司都是基于 AMD Runtime 做二次开发，完成自己的 Runtime 框架，确实可以了解一下。

## 二十二、推理岗位日常工作

有同学问：推理公司日常一天处理什么工作？

如果是推理部署，你拿到算法部门部署过来的模型，需要做多个版本的量化，比如 FP16、混精、INT8 校准量化，把推理速度和精度都测出来。弄好之后给多个版本反馈，算法部门觉得 OK，就可以部署。推理部署最大的工作基本就是量化。

如果是推理框架，一般是在做引擎上一些模块的开发和优化，也会做推理模型测试，也可能写算子。

每天工作的话，基本上都是组内开发会，或者分配任务卡。你需要领任务卡，或者 leader 开会时分配给你任务卡。接下来几天或者一周，你要在下次开会前实现这些任务。任务卡可能包含：写哪个模块，搞定某个模型推理的问题，算法部门部署时发现问题，或者算子不行要继续优化。你实现完后往下提交解决情况，组会时 leader 会听你开发情况，不是随便自己领任务。

## 二十三、美团机器学习引擎岗位

有同学问：我们组做的方向也和推理引擎有点交叉。之前有师兄说美团机器学习引擎岗简历被挂，他投的大部分都是系统架构相关岗位，最后找的工作也是系统架构。在这种情况下，是不是系统架构也可以往这方面找一点工作？

回答：我可以说一下为什么机器学习引擎岗挂了。我最后去了美团机器学习引擎岗。这个岗去年真的很卷。投的人有实习、有学历，也有很多强背景的人。比如有搞量化、发了论文的同学，也有 OSDI 背景的同学。当时有 OSDI 的同学面北斗挂了，转普通岗；也有拿了字节二面一面的同学面这个岗。反正我觉得美团这个岗真的卷，投的人也很多，有实习、有学历的人很多。

如果有 OSDI 经验，也可以投其他 OSDI 相关岗位。但如果和这些同学比，还是会有难度。
