## 3. 纠正误区：vLLM 不是一个纯 C++/CUDA 框架

老师：  
我刚才简单看了一下你的理解。你有一个误区，就是觉得 vLLM 是 C++ 加 CUDA 写的。它其实不是这样的。

在上层服务和调度层面，它是 Python 写的。什么叫服务？比如一个 HTTP 请求过来，你对大模型服务说：“请你介绍一下今天的主题。”这个上层服务其实是一个 FastAPI，这也是 Python 写的。

## 4. vLLM 的核心：调度、资源管理和显存管理

老师：  
vLLM 的上层是服务层，调度层主要是请求调度、请求切分。还有资源管理，资源管理主要就是显存管理。

你之后了解 vLLM 之后，它肯定会提到一个非常重要的东西，就是 PagedAttention。PagedAttention 本身就是对显存的一种高效管理。我之前写过一篇文章，可以给你简单看一下。

你接触过大模型，应该知道 KV Cache 这个东西吧？KV Cache 很大程度上和模型的 max context length 有关系。

在 vLLM 出现之前，通常需要给每个请求预设一个最长的对话长度，然后给它保留一整块显存。但这样有一个问题：这个请求活跃时占用了这么大一块显存，其他请求来了，哪怕这个请求现在并不活跃，或者没有被调度，这一整块显存也还是被占着。这样整体系统资源利用率就不高。

PagedAttention 的思路就是：我不要一次性给你分配一整块，而是一个请求过来之后，需要多少就分配多少小块。这些小块可以理解为 KV block。当前请求运行时，它的 KV 就存在申请到的 KV block 里。

这有点像操作系统里面页表式的管理方式。KV block 不会一次占用很大一整块显存，从而减少浪费。如果两个请求的前缀相同，这些 KV block 里面存放的 KV Cache 也可以复用。

## 5. vLLM 的代码构成：Python 为主，CUDA/Triton 用于算子

老师：  
我把这篇文章发给你，你可以大概看一下。

vLLM 在显存 block 的分配上，很多也是用 Python 写的。所以你之前理解是不对的。vLLM 前面的上层、中层，包括一部分偏底层的地方，都是用 Python 写的。

它有没有 CUDA？肯定有。你看它主仓库里 Python 代码占了大部分，CUDA 代码占了一小部分。当然，CUDA 在实际中可能还会更多，因为有一些第三方算子库没有放在主仓库里，它也会用别人实现的算子。

CUDA 用在哪里？CUDA 主要用在算子加速上。比如大模型里面的一些层：MoE 层、MLP 层、RMSNorm 层，还有刚才说到的 PagedAttention 层，这些不可能用纯 Python 写，都是用 CUDA 或 Triton 去写。

PagedAttention 的前半部分更像是管理和调度：我把当前请求放到一个映射表里。但实际计算时，底层还是要用 CUDA 或 Triton kernel 来实现。

所以 CUDA 在 vLLM 里的定位，主要是底层算子加速。

## 6. Triton 的定位：更易写的算子 DSL

老师：  
这里还有一个问题，就是 Triton。Triton 在 vLLM 里也使用挺多。

比如大模型里的 MoE，它既有 CUDA 版本，也有 Triton 版本。包括 PagedAttention，其实也有 Triton 版本。所以 Triton 和 CUDA 在定位上有一部分重叠，但 Triton 写起来更简单。

Triton 是一个基于 Python 的 DSL，也就是类 Python 语法。以前我们实现 MoE、MLP、MatMul、RMSNorm 这类算子，用 CUDA 或 CUDA C++ 写是比较痛苦的。Triton 给算子开发人员提供了一种更简单的语法。

比如你新提出了一种 Attention、新提出了一种量化算法，或者新提出了一种 MoE 结构，你现在如果用 CUDA 去调优，一方面优化成本很高，另一方面你可能只是想快速验证，然后把结果发布出来。这个时候 Triton 就非常有优势。

有些算子逻辑非常复杂，比如 MoE 就是一个逻辑非常复杂的算子。用 Triton 这种类 Python 的语法，可以快速实现。它相当于用 20% 的力气，达到 CUDA/CUTLASS 85% 到 90% 的运行性能。

但是 Triton 肯定没有办法完全取代 CUDA，因为它对底层细节的控制没有 CUDA 那么强。它更相信编译器，相信 Triton 编译器能把你的 Python-like 代码优化到比较好的程度。但最后 5% 到 10% 的优化空间，还是要靠专家级 CUDA 工程师手工调优，和底层硬件、数据流这些细节打交道。

## 12. 岗位分布：互联网、GPU公司、车企/智驾

老师：  
岗位分布其实主要有几类公司有需求。

第一类是互联网企业，比如 BAT、字节跳动、快手、抖音这些。

第二类是 GPU 企业。无论是算子，还是 vLLM，这些都和底层显卡有关。无论是 NVIDIA，还是国产 GPU 公司，比如摩尔线程、壁仞、天数智芯、寒武纪等，它们都对 vLLM 类岗位和 CUDA 算子岗位有比较大的需求。

第三类是车企和自动驾驶公司。车企包括蔚来、小鹏、理想等。自动驾驶公司和相关厂商，比如地平线、Momenta 等，也会有需求。因为自动驾驶的感知层也需要推理框架和推理加速。

不过总体来说，能冲互联网和 GPU 公司，就尽量冲前两类。车企和智驾也不错，待遇也可以。整体上这是一个比较高薪的岗位。

现在唱衰的人比较多，说这是红海。但我做这个培训三年多以来，总体感觉它是向上发展的，无论关注度、岗位 HC 数量，我目前还是看好的。

## 13. 薪资和岗位前景：只要算力不够，优化岗位就会存在

老师：  
你可能比较关心薪资。

我大概说一下。大模型算法整体薪资肯定更高，但它更看论文、更看学校。AI Infra 的薪资比传统 Java Web、前后端这些要高，但可能不如顶级大模型算法。

如果按月薪看，40K 以上基本就是 SSP 级别选手，30K 到 40K 也是比较强的 SP/SSP 区间。25K 左右可能对一些背景来说是白菜。小于 20K 的也有，但比较少。

你现在可以尽量保住 30K 以上，然后往更高冲。

至于前景，我的判断是：只要算力不够用，芯片不够用，这个岗位就一直存在。

你可以去看一些报告，无论是豆包、Kimi，还是通义千问这些，它们的请求访问量和 token 消耗量都在上升。但机器不可能一直管够，尤其现在有些 NVIDIA 芯片受限制，机器和算力之间有缺口。

在芯片不够、算力紧张的情况下，只能从软件层面做优化，让有限硬件支持更多请求。所以如果 AI 应用越来越好，推理框架、算子、AI 编译器这些岗位也会越来越重要。

硬件问题很难短期解决，所以更多还是要靠软件加速。

**这个视频告诉你：想从零冲 AI Infra，不要一上来死啃源码，而要先用 vLLM 跑通服务，再理解调度/显存管理/PagedAttention，补 CUDA/Triton 高频算子，最后用实习和项目完成求职闭环。**

**先会用，再深入。**

### 第三段：讲 vLLM 的系统结构

主讲人纠正了一个常见误区：vLLM 不是纯 C++/CUDA 框架。它的上层服务、调度、资源管理很多是 Python 写的，底层高性能算子才会用 CUDA/Triton。

这一段帮学习者理解：

**大模型推理框架是“服务系统 + 调度系统 + 资源管理 + 算子加速”的组合体。**

### 第四段：讲 PagedAttention 和 KV Cache

主讲人重点解释 vLLM 的关键技术：PagedAttention。其本质是通过类似操作系统分页的方式管理 KV Cache，避免一次性为请求预留整块显存，减少显存浪费，提高吞吐。

这一段是视频最重要的技术点之一。

### 第五段：讲 CUDA 和 Triton 的定位

CUDA 主要用于底层算子加速；Triton 是更容易写的 Python-like DSL，可以快速实现复杂算子或新算法原型，性能可能达到 CUDA/CUTLASS 的 85% 到 90%，但最后 5% 到 10% 的极致优化仍然依赖专家级 CUDA。

这一段帮助理解：

**Triton 适合快速开发和验证，CUDA 适合极致性能和底层控制。**

### 第六段：给出学习路线

主讲人建议：

1. 两周内先用起来 vLLM；
2. 然后学习调度、资源管理、PagedAttention；
3. 再学 CUDA 高频算子；
4. 继续做量化方向；
5. 尽快找实习；
6. 不要长期闭门自学；
7. 不建议主攻 llama.cpp，优先冲服务端大模型推理框架。

### 第七段：讲岗位分布、薪资和前景

岗位主要分布在：

- 互联网公司；
- GPU/AI 芯片公司；
- 车企和自动驾驶公司。

主讲人认为，只要算力和芯片紧张，AI Infra 的软件优化岗位就会长期存在。

# 4. 核心技术点提炼

## 4.1 vLLM

### 是什么

vLLM 是一个面向大模型服务端推理的高性能推理框架。

### 解决什么问题

- 提高大模型推理吞吐；
- 管理 KV Cache；
- 减少显存浪费；
- 支持多请求并发；
- 支持服务化部署；

### 视频中强调

第一阶段：会用；

### 面试可能问

- continuous batching 怎么做？
- prefix cache 有什么用？
- vLLM 上层服务怎么实现？
- vLLM 中 Python、CUDA、Triton 分别负责什么？

---

## 4.2 PagedAttention

### 是什么

PagedAttention 是 vLLM 的核心机制之一，用类似操作系统分页的方式管理 KV Cache。

### 解决什么问题

传统方式会为每个请求预留最大上下文长度对应的一整块显存，容易浪费。PagedAttention 把 KV Cache 拆成 block，需要多少分配多少，从而提升显存利用率。

### 为什么重要

大模型推理最大的瓶颈之一就是显存。PagedAttention 直接影响并发能力和吞吐。

### 面试怎么问

- 为什么普通 KV Cache 管理会浪费显存？
- PagedAttention 为什么像操作系统分页？
- KV block 怎么分配？
- prefix cache 和 PagedAttention 有什么关系？
- PagedAttention 对吞吐有什么影响？

---

## 4.3 KV Cache

### 是什么

KV Cache 是大模型自回归生成时保存历史 Key/Value 的缓存，避免每生成一个 token 都重复计算全部历史上下文。

### 为什么重要

KV Cache 占用显存巨大，是推理系统优化的核心对象。

### 面试怎么问

- 为什么要有 KV Cache？
- prefill 和 decode 阶段中 KV Cache 如何变化？
- 多请求场景下 KV Cache 为什么难管理？
- 长上下文为什么会带来显存压力？

---

## 4.4 Triton

### 是什么

Triton 是一种基于 Python 的 GPU kernel 编程 DSL，可以用类 Python 的语法写高性能算子。

### 视频中的定位

Triton 适合快速实现复杂算子和新算法原型，能够用较小开发成本达到 CUDA/CUTLASS 较高比例的性能。

### 优点

- 写起来比 CUDA 简单；
- 适合快速验证；
- 适合复杂算子；
- 和大模型推理框架结合紧密。

### 缺点

- 对底层控制不如 CUDA；
- 极致性能仍然依赖 CUDA 专家；
- 不一定适合所有场景。

### 面试怎么问

- Triton 和 CUDA 的区别是什么？
- Triton 为什么适合快速开发？
- Triton 能完全替代 CUDA 吗？
- MoE / RMSNorm / MatMul 用 Triton 写有什么优势？

---

## 4.5 CUDA

### 是什么

CUDA 是 NVIDIA GPU 的底层编程模型，是写高性能 GPU 算子的核心工具。

### 视频中的观点

即使目标岗位不是纯算子开发，也必须学 CUDA，因为：

1. 简历辨识度高；
2. 面试可能问；
3. 算子是推理框架的重要组成部分；
4. 不懂 CUDA，很难真正理解底层性能问题。

### 必学算子

- MatMul；
- Transpose；
- Softmax；
- RMSNorm；
- LayerNorm；
- Attention；
- MoE 相关算子。

### 学到什么程度

如果时间有限，不一定每个都能独立手写到极致，但至少要能讲清楚优化路径：

- naive 实现；
- shared memory 优化；
- 合并访存；
- 减少 bank conflict；
- tiling；
- Tensor Core；
- 吞吐瓶颈分析。

---

## 4.6 量化

### 是什么

量化是把模型权重或激活从 FP16/BF16 等高精度压缩到 INT8、INT4 等低精度，以降低显存、提高推理速度。

### 视频中的意义

学生已有量化背景，主讲人建议继续做，因为 vLLM 里也有量化模块，GPTQ、AWQ 等内容可以作为进入 AI Infra 的项目支点。

### 面试怎么问

- GPTQ / AWQ 是什么？
- 量化如何影响精度和速度？
- 权重量化和激活量化区别是什么？
- 量化 kernel 如何实现？
- 量化如何接入 vLLM？

# 7. 针对你的情况的建议

你和视频里的学生有相似点，也有不同点。

视频里的学生是大模型/量化背景，底层弱，目标是 26 秋招大模型推理框架。  
你的情况是：研一，预计 2027 年秋招；背景更偏嵌入式、硬件、Linux、控制系统；做过 IMS 离子迁移谱仪控制系统，接触 ESP32-S3、PlatformIO、Arduino、LVGL、TFT 屏幕、Web 控制、ADC 采样、硬件联调；你想判断是否转 AI Infra，尤其关注推理侧。

## 7.1 你适不适合转 AI Infra？

适合，但不建议完全放弃嵌入式基础去和纯 CS/算法背景学生正面硬拼。

你更适合走：

**嵌入式/Linux/系统基础 → AI 推理系统 → Runtime/端侧推理/推理框架底层模块 → 云端大模型推理框架**

这条路线可以利用你原有的差异化基础，而不是从零变成纯算法学生。

## 7.2 你更适合哪些方向？

优先级建议如下：

### 第一优先级：AI 芯片 Runtime / 系统软件 / 驱动适配

这是最贴合你嵌入式和 Linux 背景的方向。

你可以关注：

- AI 芯片 Runtime；
- NPU/GPU 驱动；
- 推理框架和硬件之间的执行层；
- 任务调度；
- 内存管理；
- kernel launch；
- 设备资源管理；
- 模型在端侧/边缘设备上的部署。

### 第二优先级：大模型推理框架

你可以学 vLLM/SGLang，但不要一开始就只看源码。先按视频建议：

1. 先跑通服务；
2. 再理解 PagedAttention、KV Cache、调度；
3. 再补 CUDA/Triton；
4. 最后做一个自己的推理优化小项目。

### 第三优先级：端侧边缘 AI

你本来就是嵌入式方向，对端侧更容易上手。可以关注：

- ONNX Runtime；
- TensorRT；
- llama.cpp；
- NCNN；
- MNN；
- RKNN；
- Jetson；
- 树莓派/嵌入式 Linux；
- NPU 模型部署。

但如果目标是高薪 AI Infra，端侧不能只停留在“会部署”，要做出性能分析和系统优化。

## 7.3 你是否应该直接冲 CUDA 算子开发？

不建议把纯 CUDA 算子开发作为唯一主线。

原因：

1. 你目前不是 GPU/HPC 背景；
2. 纯算子岗面试难度高；
3. 需要大量 GPU 架构和 CUDA 优化积累；
4. 和你的嵌入式项目不一定直接衔接。

但你必须学 CUDA 基础和高频算子。建议定位为：

**不是主攻纯算子岗，但要具备推理框架岗位需要的 CUDA/Triton 基础。**

## 7.4 你是否应该优先考虑推理引擎？

应该，但要分两层：

第一层：传统推理引擎/端侧推理  
例如 ONNX Runtime、TensorRT、MNN、NCNN，这和你的嵌入式背景更接近。

第二层：大模型推理引擎  
例如 vLLM、SGLang，这是未来更热、更高薪的方向，但学习跨度更大。

你的策略应该是：

**先用传统推理/端侧推理建立系统感，再向 vLLM/SGLang 的云端大模型推理迁移。**

## 7.5 你的 IMS 项目怎么包装？

你现在的 IMS 控制系统项目不能硬说成 AI Infra，但可以包装成“嵌入式系统工程能力”和“端侧智能化系统基础”。

可以这样表达：

- 具备嵌入式控制系统开发经验；
- 熟悉硬件采样、传感器数据链路、ADC 数据采集；
- 熟悉 MCU 控制、显示 UI、远程 Web 控制；
- 具备软硬件联调经验；
- 后续计划将传感器数据接入轻量模型，实现端侧识别和边缘推理；
- 可扩展到“端侧 AI + 传感器系统 + 嵌入式推理”。

如果你后续给 IMS 系统加一个轻量模型推理模块，例如用小模型对谱图进行分类，那这个项目就能和端侧 AI 产生真实联系。

## 7.6 你应该放弃嵌入式吗？

不应该。

你应该把嵌入式作为差异化优势，而不是包袱。

很多人学 AI Infra 是纯软件背景，但你有硬件、控制、采样、嵌入式经验。如果你再补 Linux、C++、推理框架、CUDA/Triton，你会更适合：

- AI 芯片公司；

# 9. 对你最重要的 10 个结论

1. AI Infra 不等于算法，也不等于传统嵌入式，它是模型、系统、框架、硬件之间的交叉方向。
2. 你适合转 AI Infra，但不适合完全抛弃嵌入式背景。
3. 你的最佳路线是“嵌入式/Linux → 推理系统/Runtime → 大模型推理框架”。
4. vLLM 是你理解大模型推理框架的第一核心入口。
5. 学 vLLM 不要先死啃源码，先搭服务、跑 benchmark、理解 PagedAttention。
6. CUDA 必须学，但不一定要把纯 CUDA 算子岗作为唯一目标。
7. Triton 是性价比很高的算子开发入口，适合快速建立项目。
8. 量化部署可以成为你切入 AI Infra 的一个支点。
9. IMS 项目可以和端侧 AI、传感器智能化、边缘推理结合，但需要你主动加 AI 推理模块。
10. 2027 秋招前，你必须形成至少一个“推理系统 + 性能分析 + 底层优化”的项目闭环。

# 10. 你最应该警惕的 5 个误区

1. 误区一：以为 AI Infra 只是 CUDA。  
   实际上还包括服务、调度、显存管理、推理框架、Runtime、编译器。

2. 误区二：以为会部署模型就能做 AI Infra。  
   只会部署不够，必须理解性能瓶颈和系统机制。

3. 误区三：一开始就看 vLLM 源码。  
   更好的顺序是先使用，再看机制，再看源码，再做项目。

4. 误区四：放弃嵌入式重新开始。  
   你的嵌入式/Linux/硬件基础是差异化优势，不应该丢掉。

5. 误区五：长期自学不找实习。  
   AI Infra 很看真实工程经历。学到一定程度后要尽早找实习。

# 12. 长版总结

这个视频是一段非常典型的 AI Infra 转型咨询。学生的背景是大模型方向有一定接触，但底层、硬件、CUDA 基础比较薄弱，想冲大模型推理框架岗位。主讲人没有让他一开始就死啃源码，而是给出了一条非常务实的路线：先把 vLLM 用起来，再理解它的调度、资源管理、显存管理和 PagedAttention，然后补 CUDA/Triton 高频算子，继续利用量化背景，最后尽快找实习。

视频中最核心的技术点是 vLLM 的系统结构。vLLM 不是一个纯 C++/CUDA 项目。它的上层服务、请求调度、资源管理很多是 Python 写的；底层算子加速才依赖 CUDA/Triton。PagedAttention 是 vLLM 的关键机制，它用类似操作系统分页的方式管理 KV Cache，减少显存浪费，提高推理服务并发能力和吞吐。

视频还强调，Triton 和 CUDA 的定位不同。Triton 是 Python-like DSL，适合快速实现复杂算子和新算法原型，开发效率高，但极致优化仍然要靠 CUDA。CUDA 虽然被戏称为“AI 土木”，但对 AI Infra 面试和简历辨识度非常重要，尤其是 MatMul、Softmax、Transpose、RMSNorm 等高频算子。

对你来说，这个视频的最大价值是告诉你：从嵌入式/Linux背景转 AI Infra，不应该直接抛弃原有基础去卷纯算法，也不应该只停留在端侧部署。你更适合走“嵌入式/Linux/系统基础 → 推理系统/Runtime → vLLM/SGLang 大模型推理框架”的路线。你的 IMS 控制系统项目可以作为嵌入式系统能力证明，后续如果加入轻量模型推理、谱图分类、端侧部署、性能优化，就能和端侧 AI、边缘推理产生真实联系。

你现在最该做的是：先跑通 vLLM，理解 KV Cache 和 PagedAttention；再补 CUDA/Triton 高频算子；同时把自己的 IMS 项目向“端侧 AI + 传感器推理系统”方向扩展。2027 秋招前，你需要至少一个能讲清楚性能指标、瓶颈分析和优化过程的 AI 推理项目。

# 13. 短版总结

这个视频的核心是：想从零转 AI Infra，尤其是大模型推理框架，不要一开始就死啃源码。正确顺序是先用 vLLM 搭服务，再理解请求调度、显存管理、KV Cache、PagedAttention，然后补 CUDA/Triton 高频算子，最后通过项目和实习形成简历竞争力。

对你来说，最适合的路线不是完全放弃嵌入式去卷纯算法，而是利用你已有的嵌入式、Linux、硬件联调和 IMS 控制系统经验，往 AI 推理系统、Runtime、端侧 AI、大模型推理框架底层模块靠。你应该优先学 vLLM、PagedAttention、CUDA/Triton、ONNX/TensorRT，并把 IMS 项目扩展成“端侧传感器数据 + AI 推理”的闭环项目。这样既能保留你的差异化优势，又能靠近 AI Infra 的高价值岗位。
