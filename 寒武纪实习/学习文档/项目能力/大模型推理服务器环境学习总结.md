# 大模型推理服务器环境学习总结（服务器、Docker、容器、镜像、SGLang部署流程）

## 1. 整体认知：从代码到服务器运行的完整链路

在本次对话中，核心目标是理解企业中如何在 GPU 服务器上部署和测试大模型。

完整流程：

    个人电脑
      |
      | SSH
      ↓
    公司服务器
      |
      | Docker
      ↓
    个人容器环境
      |
      ├── 镜像提供软件环境
      ├── 挂载代码和数据
      ├── 使用GPU资源
      |
      ↓
    安装推理框架（SGLang/vLLM）
      |
      ↓
    启动模型服务
      |
      ↓
    Benchmark测试性能

------------------------------------------------------------------------

# 2. 什么是服务器？

服务器本质上是一台提供服务的计算机。

它不一定长得特殊，本质和普通电脑一样：

    CPU
    RAM
    SSD
    GPU
    网卡
    操作系统

区别是：

-   性能更强
-   长时间运行
-   多人通过网络访问

对于大模型推理：

服务器主要负责：

-   保存模型
-   提供GPU计算能力
-   运行推理框架
-   对外提供模型服务

------------------------------------------------------------------------

# 3. SSH连接服务器

SSH的作用：

> 通过网络远程登录服务器，在自己的电脑终端操作远程机器。

连接需要：

    服务器IP
    用户名
    密码或SSH密钥
    端口

例如：

``` bash
ssh -p 30022 mahao@10.20.30.40
```

含义：

-   ssh：远程登录协议
-   -p 30022：SSH端口
-   mahao：用户名
-   10.20.30.40：服务器地址

登录后：

    mahao@server:~$

表示进入服务器。

------------------------------------------------------------------------

# 4. IP和端口的区别

IP：

> 找到哪台服务器。

端口：

> 找服务器上的哪个服务。

类似：

    IP = 小区地址
    端口 = 房间号

例如：

    10.20.30.40:22

表示访问SSH服务。

    10.20.30.40:8000

表示访问模型推理接口。

------------------------------------------------------------------------

# 5. 什么是镜像（Docker Image）

镜像不是图片。

它是一个已经打包好的运行环境模板。

里面包含：

    Ubuntu
    Python
    CUDA
    PyTorch
    依赖库
    推理框架

例如：

    cambricon_pytorch:v26.06

表示一个已经配置好的环境。

创建容器时：

    镜像
     |
     | docker run
     ↓
    容器

------------------------------------------------------------------------

# 6. 什么是容器（Container）

容器是基于镜像运行起来的实例。

理解：

-   镜像 = 安装好的系统模板
-   容器 = 根据模板创建出来的工作环境

容器作用：

## 1. 环境隔离

不同用户：

    用户A容器
    Python3.10
    PyTorch2.5

    用户B容器
    Python3.12
    PyTorch2.7

互不影响。

## 2. 保护服务器环境

用户安装：

    pip install
    修改依赖
    编译代码

不会污染其他用户。

------------------------------------------------------------------------

# 7. 创建容器（docker run）

典型命令：

``` bash
docker run -it \
--name my_container \
-v /data:/data \
--device GPU设备 \
镜像名称 \
/bin/bash
```

含义：

## docker run

创建并启动容器。

## -it

进入交互式终端。

## --name

给容器命名。

## -v

挂载目录。

格式：

    服务器目录:容器目录

例如：

    -v /data:/data

表示服务器/data和容器/data共享。

## --device

把GPU设备给容器。

## /bin/bash

启动Linux终端。

------------------------------------------------------------------------

# 8. 容器和文件关系（重点）

核心：

> 挂载目录不是复制，而是共享。

例如：

服务器：

    /data/model

挂载：

    容器:
    /model

两个地方看到的是同一个文件。

如果：

A、B两个容器挂载同一个目录：

    服务器/data

     |
     |--- 容器A
     |
     |--- 容器B

那么：

A修改文件：

B也能看到。

删除容器：

如果文件在挂载目录：

    文件保留

如果文件只在容器内部：

    文件删除

------------------------------------------------------------------------

# 9. 算法卷和存储卷

创建环境时：

## 算法卷

保存：

    代码
    工程
    脚本

例如：

    nano-vllm
    sglang源码
    benchmark代码

## 存储卷

保存：

    模型
    数据集
    实验结果
    checkpoint

例如：

    Qwen模型
    数据文件
    日志

# 10. 进入容器后的主要操作

进入：

``` bash
docker exec -it container_name bash
```

进入后：

看到：

    root@container:/workspace#

说明已经在容器内部。

之后大部分操作：

都在容器执行：

## 下载代码

``` bash
git clone xxx.git
```

## 安装依赖

``` bash
pip install xxx
```

## 安装框架

``` bash
bash scripts/install_sglang.sh
```

## 运行模型

``` bash
python launch_server.py
```

## 测性能

``` bash
python benchmark.py
```

# 11. SGLang安装流程理解

典型流程：

``` bash
git clone sglang
cd sglang

git checkout version

bash scripts/install_dependencies.sh

bash scripts/install_sglang.sh

bash scripts/install_sglang_mlu.sh
```

这些命令：

-   在Docker容器内部执行
-   源码保存位置取决于当前目录
-   Python依赖安装到容器环境

# 12. 测试大模型性能流程

完整流程：

## 1. 登录服务器

``` bash
ssh user@server
```

## 2. 进入容器

``` bash
docker exec -it xxx bash
```

## 3. 查看GPU

NVIDIA：

``` bash
nvidia-smi
```

寒武纪：

``` bash
cnmon
```

## 4. 进入项目

``` bash
cd /workspace/project
```

## 5. 启动模型

例如：

``` bash
python launch_server.py \
--model Qwen3-32B \
--tp 4 \
--port 8000
```

## 6. Benchmark

``` bash
python benchmark.py
```

关注指标：

    TTFT
    TPOT
    Throughput
    显存占用
    GPU利用率

# 13. 最重要的工程认知总结

企业大模型环境：

    服务器
     |
     | 提供硬件
     |
    Docker容器
     |
     | 提供隔离环境
     |
    镜像
     |
     | 提供软件环境
     |
    挂载卷
     |
     | 保存代码和数据
     |
    SGLang/vLLM
     |
     | 加载模型
     |
    Benchmark
     |
     | 测性能

一句话：

> 服务器提供计算资源，Docker容器提供隔离环境，镜像提供软件模板，挂载卷保存代码和数据，进入容器后完成模型部署、运行和性能测试。
